1债① 琥珀一色多义 → 裁决

同屏最痛场景：会话列表里「等你确认」pill（琥珀）挨着你发的消息气泡（橙），「需要你操作」与「这是你的输出」视觉不可分；同时「出包等安卓产物」（系统在忙）也用同一个琥珀。

现状语义场景（实测选择器）现状色
等你行动待确认 pill、待验收 badge（看板/Tab×2/输出物菜单）、就绪待装机看板列+手机泳道+版本号 chip、就绪待装机标题+装机按钮、验收单浮层、反馈按钮琥珀
等外部 / 进行中黄状态点（出包等产物 / 等构建）、状态 chip / 演示条强调字琥珀
警示注意通知「注意」级点+图标、设备「1 异常」、卡片副行警示字琥珀
方案 A · 两分法：琥珀 =「需要你」，蓝 =「系统在忙」
  • 琥珀收敛独占「需要你注意/行动」：等你行动 + 警示注意 合并归琥珀——两者共享「看这边」的心理指向，且都该被扫视时第一眼捕获；
  • 「等外部 / 进行中」整体迁 --info 蓝：黄点 →（等产物/等构建）、状态 chip / 演示条强调字——「系统在忙不是你的事」用冷色，与琥珀的「该你了」形成暖冷对偶；
  • 与绿点体系不冲突： 运行中（活跃）= 绿， 等外部 = 蓝， 完成/闲置 = 蓝灰——三态三点三色，语义连续。
方案 B · 三分法：再拆「警示」独立色
警示注意（通知 warn / 异常）另立橙红中间色，琥珀纯化成「待办」。语义最精确，但多一个状态色增加认知负担，且警示场景低频——收益配不上成本，仅备选。
方案 C · 维持现状 + 文档备案
不拆，只把四义写进规范。零改动，但「等你确认 vs 等安卓产物同色」的歧义永久存在——债没还，只是记了账。

2债② badge 红琥珀分裂 → 裁决

badge色位置语义（实测）
铃铛「2」红rail 🔔 + 手机 🔔未读 alert（需你行动级）
琥珀「1」琥珀看板 Tab · 手机团队 Tab · 输出物菜单待验收 / 待办计数
写死判据：红 =「不处理会出事」，琥珀 =「排着队的」
  • 红 badge = alert 专属：内容 = 通知三级里的「🔴 需你行动」（验收单待确认、成员失联、失联接替）。读掉即清零，永不转琥珀；
  • 琥珀 badge = 待办队列计数：内容 = 可排期的事项（待验收、待装机）。不读不清零，处理完才减；
  • 两色同屏时红压琥珀（红永远更少更急）——现状已天然如此（红 2 vs 琥珀 1），规范把它写死即可，无需改原型，只写判据。
