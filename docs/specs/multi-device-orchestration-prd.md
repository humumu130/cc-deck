## 1. 背景与问题

（承 v0.2 §1）双机并行是用户常态。实证痛点 A~E：跨机 PM 位语义 / worker 环境无自检 / 普通会话入队无门 / 跨机传声筒=用户 / 多用户共享桥无隔离。**新增 F~G（公司侧实测，0.2.38 旧线）**：F=Windows org CLI 两堵（路径两头拒+python3 依赖）；G=野生会话零感知 org/无 team UI/非 deck 工作不进台账。

## 2. 目标与非目标

### 2.1 目标

1. **G1 跨机会话消息路由（xmsg）**：密封信封，同租户任一机器的会话→另一机器的会话，接收侧复用既有注入链
2. **G2 PM 位跨机语义**：PM=编制角色非机器属性；跨机派单=对端权威；升级自动迁移绑定（公司侧反馈 #3）+ `org pm claim` 接管命令
3. **G3 建队完善**：装配探测+失败明确报错（B/#5）/org join 入队口+SessionStart 广播（C/#4）/跨机反馈通道（D 随 G1）
4. **G4 安全地基**：E2E 密封+设备显式互信+**设备级首次确认**（降级保留，见 4.4）+双向审计
5. **G5 多租户**：**租户=信任域硬边界（D4 拍板）**——域内全权、域间硬隔离；**登录态凭证**（设备 token 可吊销）非一次性码；**双层管理**：桥主（ADMIN_KEY bootstrap）+租户主（首个登录设备，管理本租户设备：查看/踢出/邀新/审计，主权可转移）
6. **G6 同租户自动互联**：配对码退役；入租户即互通；点选即连
7. **G7 存量迁移（D5 拍板：截止期全量）**：22 台已配对设备在截止期内全量迁入租户，逾期旧配对失效

### 2.2 非目标

- org 数据（编制/任务板）全局化（跨机只路由动作；多租户后跨租户项目共享形态重估，§9-3）
- 跨机文件系统访问；手机端新增 UI
- 完整账号 UI（注册页/找回/多码管理）——凭证与设备管理面板首版极简（列表+踢出+邀请），账号体系 UI 仍后置

## 3. 协议与架构

### 3.1 现状事实锚点（A/A2 路核实汇总）

```
CloudRouter 双形态共享：CF Worker RouterDO（cloudflare/src/worker.ts:362）+ Node 自部署桥（cloud-bridge/src/index.ts:208）——租户存储必须双形态都落（A2 P1-1）
真实信封 {to, data:{t}}；桥定向帧不检内层类型（router.ts:144-149）→ 密封 xmsg 零桥侧类型改动
设备注册现状：register 收任意 dev，rk 自洽即过（worker.ts:341-353），公钥 disc 公开——无设备名册/无租户概念/纯内存（C2 J-9：22 台身份账在 relay 侧 cloud-peers.json）
peer 通道现状=全权（COMMAND_TYPES 含 EXT_INPUT/ORG_CONFIRM/PERM）——B2 P0-1：G6 自动互联后一份凭证=全租户 relay 全权（D4 拍板接受此模型，配套见 4.4/4.5）
旧 relay 对未知密封帧静默忽略（无乒乓）；pair_req 广播全桥（router.ts:134-142）
```

### 3.2 目标协议

密封信封（外层桥只认 dev 路由，内层 E2E 设备密钥密封）：

```
{to:"rl-yyy", data:{t:"xmsg", env:"<密封>"}}
明文体 {t:"xmsg", v:1, tenant:"<tid>", source:{dev, session, role}, target:{session},
       msg_id, ts, ttl, ack_req:true, body:"≤32KB（D2，分片预留）"}
回执 {t:"xack", msg_id, state:"queued|injected|rejected:<reason>|failed"}（密封同款）
管理帧（桥侧终结，非密封中转）：{t:"login_req/login_ok/tenant_op", ...}——见 4.5
```

纪律：xmsg/xack 永远密封；管理帧走桥侧鉴权通道（ADMIN_KEY/租户主 token）；明文 xmsg 即丢。

## 4. 核心设计

### 4.1 寻址：tenant → dev → session（relay 投影帧附每会话 relay_dev 源归因）

### 4.2 发送命令面（并入既有密封 Command 通道，A 路裁决）

1. `ccops send --dev <dev> [--session <sid>] <文本>`（省略 session=发对端值班位——痛点 D 回程）
2. `org dispatch --remote <dev>`（对端权威消化；无编制回 rejected 附人话指引）
3. 会话卡远程发送按钮

### 4.3 接收口

密封解封→信任链校验→落 ext-input-queue→既有注入链→xack 四态。注入时附机器生成来源标注（不可剥离）：`⇄跨机 · 来自 <dev> 会话 <sid8> · 非本机手输`。

### 4.4 安全模型（D4 拍板版：租户硬边界+域内全权）

| 层 | 机制 |
|---|---|
| 边界-租户隔离 | 路由/广播/RELAYS/pair_req 全部租户内；跨租户=笼统拒绝（不可探测）；**null-tenant 过滤矩阵**（A2/B2：relay-online/RELAYS 等六触点逐一过滤，未迁移窗口行为定死） |
| 边界-登录凭证 | **设备登录态 token**（非一次性码）：login_req→桥侧校验邀请→签发设备 token（dev+pubkey+tenant+exp 桥签名，A2 P1-2 方案）→吊销即全租户断（活线即断+同钥不能重入，B2 踢出四缺口修死）|
| 域内-全权 | 域内设备对域内 relay=peer 全权（现状权限模型不动——D4 拍板接受，爆炸半径=租户） |
| 域内-首次确认 | **设备级** first-contact：新设备首条 xmsg/首连各弹一次确认卡（非每消息；挡新攻陷设备最快横移面） |
| 域内-审计 | 收发双向+管理操作全入 chain-audit（设备级归因）；xack rejected 发送方可见 |
| 上游-桥层 | ADMIN_KEY 桥主 bootstrap（CF=Worker secret/Node 桥=配置文件）；CLOUD_TOKEN 维持连接层 |

**G6 密钥发现配套**（A2 P1-3）：配对码退役后新手机公钥经**登录流**入桥侧名册（login_req 携带 pubkey，桥签名后 relay 从名册取）——不踩「映射复制 relay」红线。

### 4.5 租户模型（D4/D5/租户主拍板版）

- **登录与凭证**：租户主在管理面生成**邀请**（短时一次性邀请码→设备 login_req 携 pubkey+邀请码→桥验证→签发设备登录态 token 入名册）。邀请码全生命周期硬闸：高熵/一码一设备/次数预算/时效 15min/桥侧尝试限速（B2 P0-2 四件）
- **双层管理**：
  - 桥主（平台）：ADMIN_KEY bootstrap；建租户/封租户/桥级审计
  - **租户主（用户拍板新增）**：每租户首个登录设备=租户主；管理面（首版=web-console 管理页，经 relay 的桥管理代理通道打桥侧 admin API）：本租户设备列表/踢出（即吊销）/生成邀请/本租户审计查看/**主权转移**（指定另一设备为租户主）
  - 单租户自部署：桥主=租户主二合一（ADMIN_KEY 首登即兼）
- **桥侧存储（双形态，A2 P1-1）**：`tenant 表+设备名册（dev↔pubkey↔tenant↔token 态）+邀请台账+审计`——CF 形态=RouterDO storage；**Node 自部署桥=本地 JSON+内存（文件持久，同 relay org 文件域惯例）**——两形态同一存储接口（CloudRouter 注入 adapter，六触点过滤逻辑单源共享）；导出备份=管理面一键（文件/DO→下载）
- **relay 侧 SQLite**：仅 `device_trust` 一表（+pubkey 钉扎/revoked_at/confirmed_by/tenant 域字段，A2 P2 补）；本机租户身份=cloud-identity 单值；桥侧名册不复制 relay
- **同租户自动互联（G6）**：登录后 RELAYS 按租户过滤列出→端侧远程源列表自动出现→点选即连（鉴权=设备登录态）；LAN 直连场景：信任来自桥签名 token（设备名册可验），**删 v0.2 「LAN 同权」的歧义表述**（B2 P1：同钥顶替族由名册+钉扎防）
- **存量迁移（D5 截止期全量）**：迁移窗（建议 2 周）内桥主面「批量导入」——**数据源=各 relay 的 cloud-peers.json 上报**（桥侧名册收编：relay 启动时上报已配对设备清单→桥主确认入租户）；窗内旧配对直连继续有效（双轨）；**截止日旧配对失效**（提前 7/3/1 天三轮通知）；迁移连续性=最高优先验收（C2）：升级瞬间零断连、窗内零功能差异

### 4.6 PM 位跨机语义（含公司侧 #3）

升级自动迁移（relay 启动检测旧绑定会话死→自动转活 PM 或置空重选）+`org pm claim`（活 PM 会话接管命令，双机场景远端感知）；跨机派单对端权威；回执摘要回（D1）。

## 8. 验收点（v0.3 终版）

1. （承 v0.2 1-6：密封注入 30s/回程 E2E/明文拒绝/断线补发/旧 relay 零乒乓）
2. 迁移连续性（最高优先）：升级+迁移窗内**存量连接零断连零功能差异**；截止日旧配对失效如期生效且三轮通知可查
3. 登录流：邀请码→设备登录→RELAYS 只见同租户→点选即连；被踢设备活线即断+同钥重入被拒（B2 四缺口回归锚）
4. 租户主面：设备列表/踢出/邀请/审计/主权转移五操作真机通过；桥主≠租户主时权限互不越界

6. null-tenant 窗口矩阵：迁移窗内未导入设备的 RELAYS/relay-online/xmsg 行为逐一符合矩阵定义（测试矩阵入套件）
