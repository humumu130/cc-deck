1团队工作区 = 三个视图

从会话列表的团队条目进入（‹ 返回）。对话只跟 Leader，和现在的单会话一模一样；看板竖向泳道（就绪待装机置顶）+ 顶部进度总览；成员名册带三色状态与上下文水位。点 tab 切换试试。

2聊天流里只有 Leader

不是群聊——派工/汇报/Agent 间协调不进聊天流（对你全是噪音），只以提示条 + 看板红点呈现。对话末尾的打点 = Leader 正在处理，长任务不焦虑。

3你只需要回这种消息

Leader 推「📦 就绪待装机」卡片，点下载安装、看效果、一句话反馈——你永远只做最后一公里。看板 tab 上的红点数字 = 等你装机的数量。

4竖向泳道 + 进度总览

手机又细又长——泳道竖排顺着滑，「就绪待装机」置顶（你最关心的是它），已完成默认折叠。顶部一条分段进度条：1 待认领 / 2 进行中 / 1 待验收 / 1 等你装机 / 3 完成，不翻泳道也有全局感。板建在 relay 层，三端同一份数据。

驾驶舱桌面端

7网页端 = 零特权观察窗

看板、成员、时间线全可见（含给 Leader 发消息），装机确认 / 成员管理 / 发版 / 运维一律不给——网页可能开在不受控的电脑上，操作面收敛在 App 是安全边界。

≡三端同一个数据源

手机、桌面、网页看到的板，全部由 relay 同一事件流渲染（BOARD_* 事件 + 既有 last_seq 断线补发），端只做渲染差异——不另做端间同步，relay 的板是唯一事实源。

💡 与 Claude Code 内置子 Agent / teams 的区别一句话：内置是「一个会话进程内的并行」（父会话死则全死、只在终端里、同模型）；团队模式是「总线上的对等成员」（每个成员是 relay 上独立会话、互不连坐、手机指挥、状态持久化在 relay、可异构模型混编）。详见 docs/team-mode-design.md。
