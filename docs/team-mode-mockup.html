cc-deck 团队模式 · 界面形态 v5

一句话：聊天窗只有你和 Leader（长得和现在的单会话一模一样），团队的"群"在看板里。v5 回归现网面板骨架——桌面/网页/EXE 同一设计（侧栏一个分组 + 详情区三个新 Tab，会话永远全宽不被挤）；手机端三 Tab 与桌面同一套心智。两端各用各的既有配色，团队视图长在宿主设计系统里。两帧的 Tab 都可以点。

驾驶舱桌面端 & 网页端 · 同一设计

现网 web-console 骨架原样：左会话列表 + 右详情区（Tab 制）。团队模式只是侧栏多一个分组、详情区多三个 Tab——消息（与 Leader 单聊，全宽）· 看板（全宽横排泳道，宽屏的正解）· 成员 · 活动。不新开布局、不挤会话；网页端与此完全同构，仅少 EXE/Mac 的本机按钮（打开 worktree · 弹出独立窗口）。

5团队 = 侧栏一个分组

成员卡就是现有会话卡同款样式（三色状态点 + 当前任务/分支一行）。点 Leader 卡进团队详情；点成员卡 = 只读旁听该成员会话（M2+）。「＋ 开启新团队」与现有新建入口并列。

6全部长在 Tab 里，会话不被挤

消息 / 看板 / 成员 / 活动——与现有「消息·任务·全部」同一套 Tab 骨架（←/→ 键切换），互斥全宽：与 Leader 的对话永远不缩水。看板在宽屏下横排泳道全宽铺开（手机细长才竖排）。看板 Tab 上的琥珀点 = 等你装机的数量。

7驾驶舱按需开 · 网页端同构

想边聊边盯板：◱ 分屏把看板钉成右半屏，再点收起。EXE/Mac 独有：⧉ 看板弹出独立窗口（挂副屏）+ 📂 打开成员 worktree 目录。网页端（浏览器）与上图完全同构，只少这几个本机按钮——一套代码，能力探测。

指挥台手机端

随身指挥：只跟 Leader 一个对话；团队动静沉淀到看板与成员页；待装机琥珀徽标直达。三个 Tab（对话 / 看板 / 成员）与桌面端的 Tab 一一对应、同一套心智；看板为竖向泳道——顺着竖屏往下滑，「就绪待装机」置顶。

1团队工作区 = 三个 Tab

从会话列表的团队条目进入（‹ 返回）。对话只跟 Leader，和现在的单会话一模一样；看板竖向泳道（就绪待装机置顶）+ 顶部进度总览；成员名册带三色状态与上下文水位。三个 Tab 与桌面端一一对应，同一套心智。点 tab 切换试试。

2聊天流里只有 Leader

不是群聊——派工/汇报/Agent 间协调不进聊天流（对你全是噪音），只以提示条 + 看板徽标呈现。对话末尾的打点 = Leader 正在处理，长任务不焦虑。

3你只需要回这种消息

Leader 推「📦 就绪待装机」卡片，点下载安装、看效果、一句话反馈——你永远只做最后一公里。看板 tab 上的琥珀数字 = 等你装机的数量（琥珀 = 需要你行动）。

4竖向泳道 + 进度总览

手机又细又长——泳道竖排顺着滑，「就绪待装机」置顶（你最关心的是它），已完成默认折叠。顶部一条分段进度条补全局感，不翻泳道也知道团队到哪了。桌面宽屏则横排泳道——同一份数据，各用各的形态。

💡 与 Claude Code 内置子 Agent / teams 的区别一句话：内置是「一个会话进程内的并行」（父会话死则全死、只在终端里、同模型）；团队模式是「总线上的对等成员」（每个成员是 relay 上独立会话、互不连坐、手机指挥、状态持久化在 relay、可异构模型混编）。详见 docs/team-mode-design.md。
🔗 三端同源：手机、桌面、网页看到的板，全部由 relay 同一事件流渲染（BOARD_* 事件 + 既有 last_seq 断线补发）——桌面/网页本就是同一份 web-console 代码（EXE/Mac 是壳），团队视图也只做一份；手机端是独立 App，渲染竖排形态。
🔌 异构模型：每个成员可绑不同厂商的模型（编制卡上选型，凭证只存 relay 本地、永不下发端上）。默认路由：Leader 强模型 · worker 走包月便宜档 · 验收换厂商——流程独立之外再加认知独立（同厂商模型会犯一样的错）。换模型 = 同一套接替机制（板 + git 是记忆，transcript 是消耗品）：池烧穿或限流时，同身份换个模型重 spawn 即继续。
