1三个视图 = 一个团队工作区

对话：你 ↔ Leader，长得和现在的单会话一模一样。看板：团队共享任务板。成员：团队名册（身份/当前任务/分支/状态）。切到「看板」「成员」tab 看看内容。

2聊天流里只有 Leader

不是群聊——worker 的派工、汇报、Agent 间协调不进聊天流（那对你全是噪音），只以顶部这条提示条 + 看板状态变化呈现。

3你只需要回这种消息

Leader 推送「📦 就绪待装机」卡片，你点下载安装、装机看效果、一句话反馈——你永远只做最后一公里，其余全部 Agent 间消化。

4看板是共享的单一事实源

这块板建在 relay 层：你手机上看到的就是 Agent 们正在读写的同一份（认领/流转实时同步）。Claude 内置任务清单按会话隔离、互相看不见——团队模式必须重建这一层。

🖥️ 桌面端 · 驾驶舱

7网页端 = 零特权观察窗

看板、成员状态、时间线全可见（含给 Leader 发消息），成员管理 / 装机确认 / 发版 / 运维一律不给——网页端可能开在不受控的电脑上，操作面收敛在 App 是安全边界，不是功能阉割。

≡三端同一个数据源

手机、桌面、网页看到的板，全部由 relay 同一事件流渲染（BOARD_* 事件 + 既有 last_seq 断线补发），端只做渲染层差异——不另做端间同步，relay 的板是唯一事实源。

💡 与 Claude Code 内置子 Agent / teams 的区别一句话：内置是「一个会话进程内的并行」（父会话死则全死、只在终端里、同模型）；团队模式是「总线上的对等成员」（每个成员是 relay 上独立会话、互不连坐、手机指挥、状态持久化在 relay、可异构模型混编）。详见 docs/team-mode-design.md。
