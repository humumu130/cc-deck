## 双层映射说明（派单点名交付）
- **实体层（两源同 key 归并为一行）**：id=`ntf-<sha12(key)>` 前 12；category←kind、condition_key←key；level←投影 severity 直取（仅 ledger 条目按 `!actionable||system→info : resolved?done:waiting` 推导）；session_id←sourceContext.sessionId ?? source_session_id（有值写值缺 NULL）；created_at/handled_at/resolved_at 归并规则=非空优先、双方都有取较早（Math.min，确定性）；handled_at←handled_at ?? dismissed_at（全局 dismiss 下沉）；payload_json 收编两源全部剩余字段（title/body/actionable/group/sourceContext 完整+ledger 专有 first_sent_at/reminded_at/revision 进 payload.ledger 子对象）——**数据零丢失**。
- **归并语义**（同 key 双源）：投影源字段优先（R1c 投影更富）；归并发生即翻 origin 标记，同源（ledger）再遇同 key=同源重复落 duplicate-key 账（fixture 第 4 条实证）——跨源合并与同源去重不混淆。
- **client 层**：notifications.json 条目级 `client_states:[{client_id, read_at?, dismissed_at?}]`（导入器消费契约；旧 JSON 无此字段=空，符合冻结件「端侧历史若无则空」「旧 JSON 没有 per-device read 事实，迁移不推断」）；缺 client_id 记 missing-attribution 账不导行（冻结件原文）。
- **loss list 口径**：return_path 无对应实体列→每条非空 returnPath 落 unmapped-field 备注账（excerpt 记 key+return_path），payload_json 双保险不丢；returnPath 空串（decision-notify 降级合成值）不落账。
