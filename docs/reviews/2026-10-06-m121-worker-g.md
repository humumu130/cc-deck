## 二、canonical payload 设计备案（全文+理由，M12-2 依赖此口径）

### COMMAND_TASK_CREATE
```jsonc
{ "gid": "g-xxx",            // 必填，trim 后空拒
  "text": "卡文本",           // 必填，trim 后空拒
  "status": "todo",          // 可选，词表 todo|doing|done，缺省落 todo，词表外拒
  "note": "备注" }           // 可选
```
ACK：`{ok:true, data:{entity_id:"t-xxxxxxxx", gid}}`（entity_id=板卡 id）

### COMMAND_TASK_UPDATE
```jsonc
{ "gid": "g-xxx",            // 必填
  "entry_id": "t-xxxx",      // 必填，板卡不存在拒（error:"板卡不存在: t-xxx（先建卡再更新）"）
  "text": "新文本",           // **可选**——缺省从现板补旧值（见理由③）
  "status": "doing",         // 可选，词表校验同 create；缺省不动旧值
  "note": "备注" }           // 可选，缺省不动旧值
```
ACK：`{ok:true, data:{entity_id:"t-xxxx", gid}}`

### COMMAND_DISPATCH
```jsonc
{ "gid": "g-xxx",            // 可选——给了取组锚派单（组须 active）；不给走随手办，anchor_dir 必给
  "anchor_dir": "/path",     // 可选（gid 缺时生效；两者都缺派单层拒「锚目录不存在」）
  "prompt": "干这单活",       // 必填，trim 空拒
  "title": "单标题",          // 可选
  "entry_id": "t-xxxx",      // 可选——认领既有板卡（dispatchWorker 既有前置检查+认领承接）
  "role": "…", "skills": ["…"], "engine": "…", "model": "…", "provider": "…" }  // 全可选透传
```
ACK：`{ok:true, data:{entity_id:"<session_id>", gid:gid|null, dispatch_id, session_id}}`
（**entity_id=新 worker 会话 id**，dispatch_id/session_id 并列——设计稿「data 带 dispatch_id 可并列」口径）

### COMMAND_LESSON_APPEND
```jsonc
{ "gid": "g-xxx",            // 必填，板须 active（store 层 writableBoard 冻结校验）
  "text": "经验文本",         // 必填
  "tags": ["a","b"],         // 可选，store 层洗刷（去重/剔空白）
  "source_dispatch_id": "dsp-xxx" }  // 可选
```
ACK：`{ok:true, data:{entity_id:"ls-xxxxxxxx", gid}}`

### 设计理由（四条）
1. **gid 优先制**：组是 v2 编排主锚，DISPATCH 给 gid 即取组锚（anchor_dir 仅做无组随手办兜底）——M12-2 task.create→dispatch 自动链只需 payload 里带 gid 一个字段。
2. **ACK 统一 data{entity_id,gid}**：与设计稿 :160 冻结口径逐字对齐；dispatch 因含双 id（派单台账 id+会话 id）并列三键，entity_id 取 session_id（编排下游最常消费的是「会话在哪」）。
3. **TASK_UPDATE text 可选**：store 层 upsert 更新分支 text 必填，adapter 层缺省从 loadBoard 补旧值——M12-2 最常用动作是「只推 status」，不补旧值则每单都要先读板，adapter 补齐后单条命令即可，仍走单漏斗（orgAction("board")）。
4. **不新增字段语义**：全部字段映射到既有 store 层入参（upsertBoardEntry/dispatchWorker/addLesson），零新表零新文件——不建第二事实源（freeze :174 口径）。

## 三、权限能力位备案

**4 命令全走 `org:write`**（owner/operator 可用，viewer forbidden）。理由：四命令全是组织写面动作（板卡/派单/经验回流），与 COMMAND_ORG_ACTION 同权级；不新增能力位词表（org.ts 现有四能力位不动），未来 viewer 分享链接等连接级角色出现时只换 handleCommand 实参、咽喉零改（COMMAND_ORG_ACTION 先例注释同口径）。

**角色解析口径**：handleCommand 层统一传 `"owner"`（现连接面全持主 token，org.ts 不信任客户端自报角色）；测试 C6 直调 `orgCommand("viewer",…)` 验证咽喉鉴权。
