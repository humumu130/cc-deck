## 三、备案二：preflight 挂点裁定（**派单前 error**，与派单文倾向一致）

**裁定**：preflight 失败=**派单前 error**，零 spawn 零台账（dispatched 行都不落）。理由：preflight 是 which/accessSync/URL/env 级**同步静态探测**，纯检查无进程无账可记——落了 dispatched 行再收 failed 反而制造假台账行（一次派单企图两行）。与 M12-3「先落账再执行」的衔接口径：**静态检查在落账前挡，动态失败（spawn 崩）才走 dispatched→failed 收口边**——M12-3 既有 spawn 失败两口兜底保留不动（preflight 过了但进程拉起仍可能炸，动态兜底是最后防线）。

**分引擎探针**（preflightDispatchEngine 私有方法）：

| 引擎 | 探针 | 依据 |
|---|---|---|
| trae/qwen-code/codebuddy | engine-registry 探针（CLI PATH which / 绝对路径 X_OK / env 密钥引用 / base_url 解析） | preflightEngine 同步静态面，注册适配器自带 |
| codex | CLI 在场（PATH which / CCR_CODEX_PATH 绝对路径），preflightEngine 复用 | 与注册引擎同级静态探测；CodexAgentSession 一回合一进程依赖 codex 二进制 |
| claude | 恒过 | SDK 随进程内嵌（模块 import 即可用性），无可静态探针——备案为设计事实非欠账 |
| zcode | **unsupported fail-closed** | 词表内但 registry 无适配器 |

**旧态对照**：zcode/注册引擎 preflight 失败原来跑到 spawn 才炸（newAgent throw「未注册引擎/preflight 失败」→spawn 失败口收 failed 有账）——本单前移到派单前 error；newAgent throw 保留作最后防线（正常路径到不了）。

**C11⑤ 固化**：CCR_TRAE_PATH 指不存在绝对路径（accessSync 确定性失败，测试环境零依赖）→ok:false error 含「preflight 失败」+零 spawn+零台账行。
