状态灯辨识度优化桌面 web-console（橙主题）为主 · 手机 expo-app（蓝主题）轻量微调 · 全稿按首选方案 B 展示

一句话病因：黄灯不是「不够亮」，是被围住了。浅色模式下四色状态灯全部暗于白卡底（亮度差 −0.83～−0.86）——它们是「印刷墨点」，物理上发不了光；而周围全是橙：选中卡亮橙描边（与黄灯色相仅差 16°）、橙辉光、全屏橙光晕、品牌橙本身（差 20°）；ERROR 更是与品牌橙 0–2° 完全同色相（天然迷彩）。方案 B 三步走：LED 化（把灯变回发光体）＋形状编码（实心=进行中 / 空心=终态）＋暖场降噪（去橙），把状态灯从暖色噪声里捞出来。
方案 A · 保守约 6 行 CSS，只动灯自己（尺寸 / 光圈 / 色值）。浅色改善约四成——「印刷墨点」机理未根治。
★ 首选 · 本稿所示方案 B · 中庸约 18 行 CSS，不改 JS：灯系统升级（LED 化 + 形状编码）＋ 暖场降噪（选中卡去橙 / 光晕减半 / 语义色归位）。报告 §4 五条根因全部有对应项。
方案 C · 进取约 25 行：B + 卡片左缘 3px 状态条 + WORKING 整卡微染。检出效率最高，但与 hover/选中/历史/休眠四态叠加需目验调优——建议 B 落地用一周仍觉不够再上 C。
青色虚线框 = 本次变动点（不属于两端 UI） 所有卡片 / 灯 / 呼吸动画按 web-console 与 expo-app 真实代码参数复原，非抽象示意图 左右对比 = 现状（现网代码原样） → 方案 B 改后

浅色 LED 化：亮芯 + 深色环

浅色主杀器 · 直接治「灯不发光」
报告 §3.3 的结构性问题：浅色四色灯全部暗于白底（ΔL −0.83～−0.86），怎么调色值都是「墨点」。一条规则经 --sc 覆盖四状态：亮芯 = 灯色混入 45% 白（color-mix(in srgb, var(--sc) 55%, #fff)，呈「点亮的 LED」），1.5px 深环 = 原色值边界（WORKING 5.26 / WAITING 4.83 / ERROR 5.18 / DONE 5.48，全部 ≥3:1）。暗色不需要（灯本来就亮于底），维持实心。环用 border 而非 box-shadow：呼吸动画的关键帧会整体覆写 box-shadow，border 不受影响——WORKING 动画期间环不消失。
现状（浅色）
3× 放大
深色小点落在白卡上 = 印印刷墨点 / 暗斑——8px 还是 10px 都一样，这就是「黄灯被淹没」的浅色机理本体。
方案 B 改后（仅本条改动）
3× 放大 · 与①⑥叠加后的最终效果
亮芯给出发光感，深环保住边界对比。注意 WORKING（呼吸中）的青色标注环是 border——动画缩放时它跟着灯走，不消失。
