## 三、治理台账脱敏口径（哪些字段必须脱、脱成什么样）

> 适用对象：defect-ledger / ui-ledger / feedback-ledger / night-report / 三审视报告（若 D4 拍披露）。原则：**脱标识不脱事实**——结论、数字、定级 100% 保真，只动可识别到具体人/机器/基础设施的字段。

| 类 | 字段（实例） | 处理规则 | 脱成什么样 |
|---|---|---|---|
| A 凭据类 | token 值、API key、`sk-*`、cookie、配对码实例 | **绝不出现**，披露前机检拦截 | 删除或 `***`；机检 pattern 至少含：`(/Users|/home)/\w+`、`(sk-|token|key)\s*[:=]\s*\S{8,}`、`\d+\.\d+\.\d+\.\d+`、`:7890` |
| B 个人标识 | 用户名、`/Users/xdd` 家目录路径、设备名（home-mac/shac-win/homewin 等）、公司名与内部项目名（DIP 等） | 泛化映射表统一改写 | `developer`／`~/`／`PC-1/PC-2/PC-3`／「某内部项目」；映射表本身不随披露发布 |
| C 内部基础设施 | ECS IP/域名、KV 存储、代理端口 7890、自建桥地址、内部服务 URL | 删除或泛化 | 「自托管服务器」「自建中继」；**公共桥**的限流/行为参数属产品公开行为，保留 |
| D 内部平台引用 | DEV-xx 单号、multica/MUL-xx、org 板面文件名、`~/.claude/projects/…` 转录路径 | 单号保留（无敏感、且是可追溯性的展示），内部链接去活，转录路径删 | 「（内部工单 DEV-xx）」样式 |
| E 用户原话引用 | 台账/报告中的用户语句 | 现象保留，可识别个人/公司的细节删，频次计数保留 | 例：「11-17 三台机器同账号」→「三台机器同账号（11-17）」 |
| F 未修复缺陷细节 | defect-ledger 活故障条目、未修复安全弱点 | **分池**：已闭环条目可全量；未闭环 P0/P1 只保留「类别＋状态＋负责人」，技术细节延迟到修复后发布 | 防「照着台账打活系统」——LAN token/无 TLS 等已是 README 公开的安全模型 trade-off，不算新增暴露；其余从严 |
| G 日志/数据样例 | events.ndjson 摘录、板面文件片段 | 路径泛化＋值重制 | 结构保真、值为示意值 |

**落地形式**（一批量级）：`scripts/redact-ledger.mjs`（白名单字段改写＋上表 A 类 pattern grep 闸，命中即退出非零）→ 产出到 `docs/public/`（或独立仓库，随 D1 版本 A 定）→ 人工复核一轮（E/F 类机检不了一刀切的）→ README「治理能力」节挂链接。

**验收**：①披露材料过 grep 闸零命中；②抽 10 条与原账对照，结论/定级/计数零改动；③模拟外部读者复读，无内部指代迷航（D 类样式统一）。
