# 桌面端会话卡状态灯显眼度问题分析与设计方案

> v2（2026-09-20 覆盖更新）· 视觉/前端专题分析 · 只出方案不改代码，落地项待用户拍板
> **v2 变更**：用户澄清两端**均使用浅色模式**——原 v1 主打数据为暗色口径。本版补齐浅色主题完整量化分析（§3.1/§3.2/§3.3），并据此修正方案（亮色 `--working` 候选从 `#B45309` 改为 `#8F6400`，新增浅色专属"LED 化"处理），全文表格改为明暗双列。
> 涉及文件：`web-console/index.html`（单文件 SPA，行号以当前工作区为准）、`expo-app/src/theme.ts`、`expo-app/src/screens/ListScreen.tsx`

## 1. 问题复述

用户反馈（原意归纳）：

1. 桌面端（web-console，Tauri 内嵌）主题大量使用橙色品牌色，会话卡上的**黄色 WORKING 状态灯被橙色淹没**，无法一眼识别哪些会话在跑；
2. **绿色（DONE/空闲）区分度也不够**；
3. 手机端（expo-app）观感明显更好，要求找出差异原因；
4. 补充输入（2026-09-20）：手机端也有**轻微同感**，怀疑面板黄色元素偏多（用户自述不确定，本次已验证，见 §2.2/§5.4）；手机端一并纳入分析，方案给可选轻量微调，**优先级桌面端 > 手机端**；
5. **澄清（2026-09-20）**：桌面与手机**都用浅色模式**——分析重心落在浅色主题，暗色数据保留作双列对照。

一处事实修正：状态灯不在"卡片右上角"，而在**标题行最左侧**（`c-head` 内、标题文字之前）；标题行右端是总耗时。这不影响问题成立，但改动定位应以标题行左端为准。

## 3. 量化对比（WCAG 2.x 公式；非文本组件达标线 3:1，小号文字 AA 4.5:1）

### 3.1 状态灯 vs 卡片底色对比度（明暗双列 · ★=用户实际所见）

| 底色组合 | WORKING | WAITING | ERROR | DONE | 品牌橙参照 |
|---|---|---|---|---|---|
| 桌面 **暗** 卡底 `#0B141F` | `#FFC53D` **11.73:1** | 5.31:1 | 7.08:1 | 10.07:1 | `#D97757` 5.93:1 |
| 桌面 **★浅** 卡底 `#FFFFFF` | `#A16207` **4.92:1** | 4.83:1 | 5.18:1 | 5.48:1 | `#C2603E` 4.17:1；亮橙线 `#E07B4C` 仅 2.95:1 |
| 桌面 **★浅** hover `#F1F4F9` | 4.47:1 | 4.38:1 | 4.70:1 | 4.97:1 | — |
| 手机 **暗** 卡底 `#0B1622` | 11.55:1 | 5.23:1 | 6.97:1 | 9.92:1 | — |
| 手机 **★浅** 卡底 `#F2F3EE` | **4.41:1** | 4.33:1 | 4.64:1 | 4.92:1 | — |
| 手机 **★浅** panel2 `#E2E4DC` | 3.84:1 | — | — | 4.27:1 | — |

**读数（浅色口径）**：四色全部 ≥3:1 达标，且 WORKING **不是**数值最弱（WAITING 更低）——**"黄灯看不清"在浅色下同样不是对比度问题**。附带发现两处小号黄字跌破文字 AA：桌面 `lv-sec` 对 hover 底 4.47:1、手机 LiveStat 对米白底 4.41:1（§5 一并修）。

### 3.2 色相距离（HSV hue，明暗对比 · ★=用户实际所见）

| 配对 | 暗色 | ★浅色 | 结论 |
|---|---|---|---|
| WORKING vs 品牌橙 `--brand` | 27° | **20°** | 浅色更挤 |
| WORKING vs 选中卡描边 `--brand-line` | 27°（=brand） | **16°**（`#E07B4C`） | 浅色最挤：黄灯贴着亮橙线 |
| ERROR vs 品牌橙 | **0°** | **2°** | 两主题均完全撞色（天然迷彩） |
| DONE vs 品牌橙 | 139° | 148° | 绿色相安全，弱在别处（见 3.3） |

### 3.3 发光性检验（灯与底的相对亮度差 ΔL——浅色痛点的真正量化）

| 组合 | 灯 L | 底 L | ΔL | 观感机理 |
|---|---|---|---|---|
| 暗色四色 vs 暗卡底 | 0.25–0.62 | 0.007 | **+0.25 ~ +0.61** | 灯**亮于**底 = 发光体，自带"点亮"感 |
| ★浅色四色 vs 白卡底 | 0.14–0.17 | 1.000 | **−0.83 ~ −0.86** | 灯全部**暗于**底 = 印刷墨点，物理上不可能有"灯感" |

这是两端共用同一套浅色状态色（文字级深色）的结构性后果：**浅色主题的状态灯是"深色小点"而非"发光体"**，8px 的深琥珀点落在白卡 + 淡橙雾 + 亮橙描边的暖环境里，观感=一粒暗斑——这就是用户"黄灯被淹没、绿灯区分不出"的浅色模式机理。

### 3.4 几何视角（96dpi，桌面视距 55cm / 手机 30cm 估算）

- 桌面 8px 灯 ≈ **13.2 角分**；手机 11dp 灯 ≈ **33.4 角分**（2.5 倍）；面积另差 1.9 倍。

## 4. 差异根因（按权重；标注作用主题）

1. **浅色：亮度倒置，灯无"发光感"（★主因，§3.3）**——四色灯全部暗于白底，退化成印刷点；品牌橙环境再一围，深琥珀点直接融进暖色调。
2. **色相拥挤，浅色更严重（主因，§3.2）**——浅色 WORKING 距品牌橙 20°、距选中卡亮橙描边仅 16°（暗色 27°）；ERROR 两主题均与品牌橙 0–2° 重合。桌面 75 处橙引用 vs 手机蓝紫品牌，是两端观感差异的最大单因。
3. **灯体几何（次因，两端共用）**——8px vs 11px（面积 1.9 倍）+ 视距，综合视角差 2.5 倍。
4. **静态无分层（次因）**——静止态裸色点贴卡面，无 halo/描边/形状差异；呼吸动画的 scale 幅度（8px→6.4px）肉眼难辨，只剩轻微闪烁。
5. **语义色混用（加重项）**——WAITING 卡整行黄字（1422 行）、`.del` 用橙系 `--error`；手机 LiveStat 整行黄字 + 黄统计数字同病（程度轻）。

## 5. 设计方案（保守 → 进取；**方案 B 为首选**；★=浅色重点项）

> 三案均只改 `web-console/index.html`；手机端默认不动，可选微调见 5.4。

### 方案 A · 保守「灯自身增强」（约 6 行 CSS，零布局风险）

| 改动点 | 现值（行号） | 新值 | 浅色表现 |
|---|---|---|---|
| 灯尺寸 | `.c-dot` 8px（1239） | `10px` | 面积 +56%，明暗同受益 |
| 静态光圈 | 无 | `.c-dot { box-shadow: 0 0 0 3px color-mix(in srgb, var(--sc) 20%, transparent); }` | ★白底上呈淡彩圈，深点+彩圈组成"指示徽"而非裸斑点；WORKING 呼吸动画的 box-shadow 关键帧会自然接管为动态光晕（预期行为） |
| 暗色 `--working` | `#FFC53D`（41） | `#FFD84D`（47°，暗底 13.39:1） | 不影响浅色 |
| ★浅色 `--working` | `#A16207`（86） | **`#8F6400`**（42°；白底 5.26:1、hover 底 4.77:1、米白 4.72:1） | 色相 35°→42°，与品牌橙拉开到 27°（=暗色水准）；顺带修复 `lv-sec` 黄字 hover 底 4.47:1 的 AA 超标。**v1 曾建议 `#B45309`（26°）——经复核距品牌橙仅 11°，比现状更近，弃用** |
| 暗色 `--waiting` | `#F0524F`（42） | `#FF6B68`（暗底 6.66:1） | 不影响浅色 |

- 不加新动效；亮色 `--waiting/--error/--done` 不动（均达标）。
- 浅色预期：改善约四成——"印刷点"机理（§3.3）未根治。

### 方案 B · 中庸「灯系统升级 + 暖场降噪」（**首选**，约 18 行 CSS，不改 JS）

方案 A 全部内容，另加四条结构性修正：

1. **★浅色灯"LED 化"（浅色主杀器，直接治 §3.3 亮度倒置）**：
   ```css
   html.light .card .c-dot {
     background: color-mix(in srgb, var(--sc) 55%, #fff);   /* 亮芯：白话=灯色提亮 45%，呈"点亮的 LED" */
     border: 1.5px solid var(--sc);                          /* 深环：提供边界对比（4.9–5.5:1，全部≥3:1） */
   }
   ```
   - 一条规则经 `--sc` 覆盖四状态：亮芯给出"发光感"，深环保住 WCAG 边界对比（环色即原色值：WORKING 5.26:1 / WAITING 4.83:1 / ERROR 5.18:1 / DONE 5.48:1，全达标）。
   - 用 `border` 而非 `box-shadow` 做环：呼吸动画关键帧会整体覆写 box-shadow，border 不受影响，WORKING 动画期间环不消失。
   - 暗色不需要此处理（灯本来就亮于底），维持实心。
2. **形状编码：终态空心化**（直接回答"绿黄难分"，明暗同规则）：
   - `.card.DONE .c-dot { background: transparent; border: 2px solid var(--done); }`
   - `.card.ERROR .c-dot { background: transparent; border: 2px solid var(--error); }`
   - render 已把状态写成卡片类名（4222 行 `d.className = "card " + s.status`），**纯 CSS 实现，零 JS 改动**。浅色下 2px `#047857` 环对白底 5.48:1，清晰。
   - 效果：WORKING/WAITING = 实心亮点（在跑/要处理），DONE/ERROR = 空心环（终态退后）。扫列表 = 只找实心亮点。
   - 注意与第 1 条的叠加顺序：`.card.DONE .c-dot` 规则写在 `html.light .card .c-dot` 之后（或提高选择器特异性），浅色 DONE = 空心环不受 LED 亮芯影响。
3. **选中卡橙辉光降档**（拿掉列表最大常驻橙，明暗同改）：
   - 1144 行 `.card.sel` 投影 `rgba(217,119,87,.15)` → 中性：暗 `rgba(0,0,0,.35)` / 浅 `rgba(15,23,42,.12)`（新变量 `--sel-shadow`）；1px 品牌描边保留。★浅色下同时建议 `--brand-line` 选中卡用途降一档亮度（`#E07B4C` 2.95:1 本身就偏浮），可新增 `--sel-line: #C2603E` 供 `.card.sel` 使用——描边仍在，但不再以一条高亮橙线贴着黄灯。
4. **body 橙光晕减半 + 语义色修正**：
   - 124–125 行 alpha `.08→.04`、`.05→.03`（浅色下这层淡暖雾虽弱，但方向一致顺手减半）。
   - 1422 行 `.card-summary.waiting` 色 `var(--working)` → `var(--waiting)`——WAITING 卡文字回归红语义，黄只留给"在跑"。

- **浅色综合表现**：LED 化（治"不发光"）+ 42° 琥珀（拉开色相）+ 10px+光圈（几何）+ 终态空心（形状编码）+ 去橙降噪（环境）——§4 五条根因全部有对应项。
- 暗色表现：同 v1（尺寸/光圈/色值/空心环/去橙）。
- 回归关注：`--working` 浅色新值 `#8F6400` 波及 runhint、connChip、审批卡黄底文字、`.f-data` 图标（1393 行硬编码 `#A16207` 不受影响）等 10 余处——全为同向受益（对比度↑），审批卡浅色底 `#FFF6DE`（114 行硬编码）需目验一次。

### 方案 C · 进取「左缘状态条 + WORKING 整卡微染」（约 25 行，需目验调优）

方案 B 全部内容，再加：

1. **卡片左缘 3px 状态条**：`.card::before` 纵条（`background: var(--sc)`，由 `.card.WORKING/.WAITING/.ERROR` 注入，DONE 无条）。★浅色下 3px 深色条对白卡对比 4.9–5.5:1，检出效率远高于点状信号，且不受"发光感"机理制约——浅色模式下此案收益比暗色更大。
2. **WORKING 整卡微染**：暗色 5%（染后 `#171e21`，标题 14.45:1 / 正文 11.15:1 / 灯 12.20:1，全远超 AA）；★浅色 5% 染白卡 ≈ `#FCF8F1` 过弱，需 8–10% 起步（≈ `#FAF3E3` 档）实测定稿，且 hover 态需配染色变体防"闪断"。
3. 风险：与 hover/sel/historical/dormant 四态叠加调和成本高。建议 B 落地使用一周仍觉不够再上 C。
