# 收工交接（/handoff）

用户要收工（或你判断本会话该收口）时，按以下四步走完，顺序固定。全程不派新单、不开新工作——这是收尾流程，不是继续干活。

## 第一步：盘点

TaskList 全量拉取，逐条给出现状：
- pending：卡在哪（等依赖/等拍板/纯排队），下一步一句话；
- in_progress：已完成什么、进行到哪一步、下一步、涉及文件路径、未决问题；
- 已带 `[搁置]`/`[常驻]` 标记的：注明不动。
有「做完但没收割」的（改了没提交、提交了没 squash、回执没写），逐条列进环境态清单。

## 第二步：固化

1. 按 memory 命名惯例写接续锚文件（`ccdeck-<MMDD>-<主题>-state.md`）：当前批次状态/在办与接续点/环境状态（后台构建、relay、设备连接）/关键决策与用户口径。写的时候假设接任会话**只读 memory 就能无损接棒**——拿不准的信息宁可多写。
2. 把锚文件的索引行插进 memory 索引（MEMORY.md）**顶部**，带「最新」标记。
3. 扫一遍索引里**其他带「最新」标记的旧条目**：已被本次更新覆盖的，把它们的「最新」字样去掉（防多「最新」漂移——索引里同时存在多个「最新」=接任会话不知道该读哪条）。

## 第三步：环境态清单

逐项清点并列给用户（有则列，无则跳过）：
- 在途构建/CI：哪个通道、起于何时、预计何时好、产物将落在哪；
- relay/服务进程：是否有你起的临时进程需要停（测试实例、mock relay、端口占用）；
- 设备连接：测试机/模拟器连接态；
- 分支与 worktree：本会话开的分支是否已 squash 回主干、worktree 是否可删（**只清点不执行**——删除等用户发话或接任会话核实后做）；
- 待回填验收单：单号与双链；
- 未 push 的提交：分支名与笔数。

## 第四步：收尾

1. 向用户明确列出：剩余项（按接续顺序排）、本会话完成项一句话各带证据（提交号/回执路径）。
2. 有重量级产物（设计文档/调研报告/拍板表）没登记的，顺手 deliver 登记。
3. 用户确认收工后，本会话不再接新任务；有新需求就明确建议「入单下个会话接续」。

## 纪律

- 全程只写 memory 与报告，不动代码、不动规则文件、不删 worktree/分支。
- 「最新」标记全索引至多保留 1~2 条真正最新的，其余一律降级。
- 状态固化以「接任会话零上下文可接棒」为验收线——写完自查一遍：只看 memory 锚，能否答出「做到哪了/下一步/环境里有什么在跑」。
