# cc-deck A 方向完整设计规范

版本：A / Command Bridge · 2026-10-03  
输入：`specs/002-redesign-proposals.md`、`specs/003-redesign-sketches.html`、`specs/001-ia-freeze.md` 及现有功能基线。  
设计目标：把 cc-deck 做成面向行动的指挥桥——左侧看全局，第二栏决定先做什么，主工作区执行，右侧检查证据。

## 1. 设计决议

### 1.1 主心智

cc-deck 的首要问题不是“我有哪些页面”，而是“现在有哪些事情需要我处理，以及我如何确认它已经完成”。因此默认工作面以行动优先，但不得牺牲传统会话浏览：

- 桌面会话域第二栏默认显示「行动队列」，提供同层级的「全部会话」切换。
- 「全部会话」按项目分组，保留会话名称、来源、状态、最近活动和上下文水位等传统浏览信息。
- 手机会话 root 与桌面同源：默认「待处理收件箱」，可切换「全部会话」；点击会话进入全屏详情，详情页隐藏底栏。

### 1.2 四层结构

| 层级 | 责任 | 桌面形态 | 手机对应 |
|---|---|---|---|
| 域栏 Domain Rail | 切换一级工作域、连接快览、通知入口 | 左侧固定窄栏 | 底部四 Tab；通知在 root 顶栏铃铛 |
| 行动队列 Action Queue | 当前域的优先级、筛选、实体入口 | 域栏右侧固定第二栏 | root 首屏的列表/卡片；不常驻于详情 |
| 主工作区 Main Workspace | 当前实体的核心内容与主动作 | 中央可滚动主区 | 单列全屏详情或 root 内容 |
| 证据检查器 Evidence Inspector | 任务、状态、用量、成员、产物和来源证据 | 右侧可收起检查器 | 详情内分段、半屏 sheet 或底部动作区 |

四层不是四个必须同时可见的面板：桌面宽屏默认全显；窗口不足 1180px 时检查器收起为按钮，窗口不足 920px 时行动队列转为可展开抽屉；手机永远采用单列深入。

## 2. 信息架构定稿

### 2.1 域栏最终清单

域栏从上到下固定如下：

1. **连接状态点**：绿=在线，琥珀=连接中/部分异常，红=断开或需配对；点击打开连接快览，不改变当前域。
2. **会话**：默认启动域；承载行动队列、全部会话、会话详情。
3. **团队**：承载团队列表、团队作战室、成员、派单、任务板和确认卡。
4. **项目**：承载按目录聚合的只读项目观测台。
5. **弹性空位**：视觉分隔，不承载未来功能占位。
6. **通知铃铛**：跨域行动入口；badge 只计需用户行动的 alert，不是消息未读数。
7. **设置**：承载连接与设备、配对、模型服务、显示/快捷键、身份模板、扩展、关于。

域栏选中态只允许一个内容域。通知面板是工具态，不覆盖当前域的选中态；连接快览同理。

### 2.2 行动队列的域映射

| 当前域 | 第二栏标题 | 默认分组 | 卡片必须显示 | 主动作倾向 |
|---|---|---|---|---|
| 会话 | 待我处理 | 需行动、运行中、最近完成 | 会话名、项目、状态点、等待原因/摘要、最近活动、上下文水位 | 打开会话、去任务/验收、恢复会话 |
| 团队 | 团队行动 | 待确认、进行中、待验收、已归档 | 团队名、成员数、任务进度、待处理数量、最近活动 | 打开团队、确认编制、进入看板 |
| 项目 | 项目观测 | 活跃项目、存在风险、已隐藏 | 目录、会话数、团队数、输出物数、需行动数 | 查看聚合、跳原始域 |
| 通知 | 需你行动 | 需你行动、注意、动态 | alert 标题、来源域、发生时间、行动标签 | 立即处理、跳原始来源 |
| 设置 | 设置导航 | 连接与设备、模型服务、偏好、团队身份、扩展、关于 | 分组标题、当前状态、异常提示 | 打开设置子页 |

### 2.3 主工作区与证据检查器

- 主工作区同一时刻只服务一个“当前实体”。队列卡选中后，主区标题、状态、段签和检查器必须同步更新。
- 主工作区顶部固定实体标题、来源/路径、状态标签和局部段签；主内容区可滚动；主动作不随长内容消失。
- 证据检查器默认显示当前实体最重要的 3—5 项证据，不做信息仓库。超出部分进入“查看全部”或对应段签。
- 检查器可收起；收起后保留一枚可见的“证据”按钮和待处理数量，不得让用户失去当前风险提示。
- 项目域检查器显示来源链路和聚合计数，不出现编辑按钮；所有写操作按钮文案必须明确“在会话中处理”或“在团队中处理”。

## 3. 各域关键屏与状态口径

状态口径统一为：正常态展示真实数据；空态解释为什么为空并给下一步；加载态保留结构不跳动；错误态说明影响范围并给最小恢复动作。

### 3.1 会话域

**关键屏：行动驾驶舱、全部会话浏览、会话详情。**

| 状态 | 行动队列/主区表现 | 用户下一步 |
|---|---|---|
| 正常态 | 「行动队列」默认选中；可切到「全部会话」，按项目分组显示 `cc-deck`、`windclaw-qclaw` 等项目；详情显示对话、任务、输出物、用量、等待卡和附件 | 点击队列卡进入详情；点击局部段签定位内容；主动作固定在输入/动作栏 |
| 空态 | 无行动项时显示“暂无待你处理”，下方保留「全部会话」入口；无任何会话时显示“还没有会话”与「新建会话」 | 切到全部会话、刷新、创建会话或去设置配对 |
| 加载态 | 队列保留三组骨架卡；主区保留标题骨架、时间线骨架和检查器骨架；不把已有内容整体清空 | 用户可以返回或切换域；禁止对未加载卡执行动作 |
| 错误态 | 队列顶部显示连接/事件流异常；缓存数据降级为只读并标记“数据可能过期”；主区显示最后更新时间 | 「重连」「打开连接设置」；重连成功后原位置恢复 |

会话详情局部段签固定顺序：`对话`、`任务`、`输出物`、`用量`；低频的定时任务、全部日志、权限细节收进 `⋯`，但不删除能力。

### 3.2 团队域

**关键屏：团队行动队列、团队作战室、成员/派单/确认检查器。**

| 状态 | 行动队列/主区表现 | 用户下一步 |
|---|---|---|
| 正常态 | 队列按待确认、进行中、待验收、已归档分组；主区默认团队看板，显示待认领、进行中、待验收、待装机、完成泳道；检查器显示成员和派单证据 | 开团、确认编制、拖动/改派任务、打开成员、填写/确认验收单 |
| 空态 | 无团队时显示开团四步说明；无行动时显示“团队运行正常”；归档为空不报错 | 「新建团队」「查看已归档」 |
| 加载态 | 团队卡、泳道列和成员行使用固定高度骨架；保留团队标题和连接状态 | 等待快照；可切换域但不对骨架操作 |
| 错误态 | 如果事件流断开，主区保留最近快照并显示“只读/更新时间”；如果单个成员失联，标红成员并保留接替入口 | 重连、换厂商接替、打开连接设置；不得误报为整个团队失败 |

团队详情段签顺序：`对话`、`看板`、`成员`、`活动`。对话只留目标、范围和决策；认领、提交、停滞等动静进入看板/活动。

### 3.3 项目域

**关键屏：项目观测台、项目详情四分节。**

| 状态 | 行动队列/主区表现 | 用户下一步 |
|---|---|---|
| 正常态 | 按目录聚合会话、团队、输出物、验收单；主区显示路径、活跃数、风险数和只读标识；检查器显示来源链路 | 查看聚合、跳到原始会话/团队、打开输出物或验收来源 |
| 空态 | 未发现项目时说明“按目录自动识别”，提供「打开目录」或「刷新扫描」；无风险时明确“暂无需行动” | 打开目录、刷新扫描、回会话域新建会话 |
| 加载态 | 项目列表保留目录行骨架，主区保留四分节骨架；扫描中显示进度而不是空白 | 等待扫描；允许离开并在后台完成 |
| 错误态 | 目录不可访问、realpath 失效或聚合源异常时，标记具体项目/来源，不把整个项目列表置红 | 「重新扫描」「在会话中查看来源」；项目域本身不提供修复写操作 |

项目四分节固定为：`会话`、`团队`、`输出物`、`验收单`。它们是只读聚合视图，不是四套新的编辑面。

### 3.4 设置域

**关键屏：设置导航、连接与设备、模型服务、偏好/身份/扩展。**

| 状态 | 行动队列/主区表现 | 用户下一步 |
|---|---|---|
| 正常态 | 第二栏显示设置分组和异常提示；主区显示当前设置页；检查器显示当前连接、凭证存储边界和同步状态 | 编辑连接、验证模型服务、调整偏好、查看身份模板/扩展 |
| 空态 | 未配置 relay/设备时显示“尚未配对”，提供配对码/扫码入口；未登记 provider 时说明默认继承本机环境 | 配对设备、添加连接、回电脑/网页录入凭证 |
| 加载态 | 服务器、设备、provider 行显示骨架；保留设置标题和返回位置 | 等待读取；不可提交未完成表单 |
| 错误态 | 按连接、设备、provider 分项报错；表单保留用户已填值；不把单个设备错误扩散为全局离线 | 重试、重配对、换路由、打开帮助；显示最后成功时间 |

设置子页建议：`通用`、`模型服务`、`连接与设备`、`团队身份模板`、`扩展`、`关于`。手机为浏览/验证/换路由优先，凭证录入回电脑或网页端。

### 3.5 通知域

**关键屏：通知面板、通知与验收工作台。**

| 状态 | 行动队列/主区表现 | 用户下一步 |
|---|---|---|
| 正常态 | 队列分需你行动、注意、动态；badge 只取第一组；主区展示验收单、接替、配对或连接处理；检查器显示来源实体 | 立即处理、跳原始来源、关闭/标记已处理 |
| 空态 | 显示“暂无需要你行动的通知”；可切看历史动态但不伪造 badge | 回当前域或查看动态历史 |
| 加载态 | 按分组显示通知骨架；保留铃铛标题和当前域上下文 | 等待事件流；不因加载自动清零 |
| 错误态 | 显示“通知可能未同步”和最后同步时间；已缓存 alert 保留红色风险标识 | 重试同步、打开连接设置；不把缓存 alert 静默隐藏 |

通知 badge 沿用 `specs/001-ia-freeze.md`：只计 active、需用户行动的 alert；普通动态、warning/info、任务完成汇报不计入；打开面板不自动清零，执行动作或明确处理后清零。

## 4. 交互规则

### 4.1 跨域跳转与来源返回栈

#### 跳转模型

- 域栏切换是一级切换，不等同于返回；每个域可以保存最近队列筛选、选中实体和滚动位置。
- 项目聚合卡、通知 alert、验收单入口必须携带 `sourceContext`：来源域、来源详情、来源滚动锚点、来源子视图。
- 写操作只在原始域执行：项目卡的“查看会话/团队”与通知的“去处理”都是带来源上下文的跳转。
- 桌面 URL/history 至少恢复域、实体、局部段签；刷新后按域 → 详情 → 段签顺序恢复。

#### 返回优先级

1. 先关闭当前弹窗、sheet、通知面板、连接快览或检查器浮层。
2. 处于详情时回 `sourceContext`，不能无条件回会话首页。
3. 从项目跳到会话/团队，返回项目详情并恢复原项目滚动位置。
4. 从通知跳到原始处理页，返回通知工作台；再次返回才回进入通知前的域。
5. 已在 root 时，桌面交给 history，手机回上一个 root 或执行系统退出。

动画期间的返回动作不能被静默吞掉；进入/退出动画完成后必须恢复可消费状态。

### 4.2 局部视图段签

- 段签只描述当前实体的内容切片，不承担一级域切换。
- 默认段签只放高频 3—4 项；低频能力进入 `⋯`，但菜单标题必须带出待处理数量。
- 段签顺序跨端一致，桌面可横排，手机可横滑；当前段签用底部 2px 暖橙线和高亮文字，不用大面积橙底。
- 点击任务引用、输出物、验收卡时，先切到对应段签，再定位到具体行；找不到历史行时只切段签，不弹错误。
- 段签切换不改变来源返回栈；桌面同步 history，手机保留页面内部状态。

### 4.3 主动作固定位置

- 会话：输入/附件/发送固定主工作区底部；等待卡的“允许一次/拒绝并说明”固定在等待卡内部，避免用户滚到底部找审批。
- 团队：开团、确认编制、派单、接替固定在当前团队/成员检查器底部；看板卡上的主动作不超过一个。
- 项目：不出现“保存/编辑/确认”主按钮；只允许“查看来源”“在会话中处理”“在团队中处理”。
- 通知/验收：主区底部固定当前阶段动作；提交回填后原位变为“确认收单”，不把用户送到新页面。
- 设置：表单页底部固定保存/验证；连接页的重配对/踢出按设备行就近放置，危险动作二次确认。
- 手机详情：主动作随底部输入栏/动作栏固定；全局底栏隐藏，避免两个底部动作层叠。

### 4.4 队列行为

- 队列卡点击即选中并联动主区/检查器；单击不直接执行危险动作。
- 会话域第二栏顶部固定切换：`行动队列` / `全部会话`。行动队列按行动优先级分组；全部会话按项目分组，并保留搜索、来源过滤和状态过滤。
- 选择“全部会话”不清除行动 badge；切回行动队列时保留上一次选中的行动卡。
- 队列更新时只更新受影响卡片；不得因一条事件刷新导致滚动位置跳回顶部。

## 5. 视觉规范

### 5.1 色板

| Token | 色值 | 用途 |
|---|---|---|
| `bg-0` | `#050B12` | 应用最深背景、域栏 |
| `bg-1` | `#0A111B` | 主工作区背景 |
| `surface-1` | `#0D1826` | 行动队列、检查器底 |
| `surface-2` | `#122235` | 卡片、输入区、次级面板 |
| `surface-hover` | `#192D43` | hover/选中前景 |
| `line` | `#243448` | 主要边框和分隔线 |
| `line-soft` | `#1B293A` | 弱分隔、列表组线 |
| `text-strong` | `#E8EFF8` | 标题、当前实体、主按钮文字 |
| `text` | `#C4D0DE` | 正文和常规标签 |
| `text-dim` | `#8394A9` | 元信息、次级说明 |
| `text-faint` | `#53677E` | 占位、禁用、时间戳 |
| `brand` | `#D97757` | 暖橙行动色、选中线、主动作 |
| `brand-hover` | `#E8985F` | hover、焦点和浅色强调 |
| `brand-soft` | `#2B1D1A` | 暖橙弱底、选中卡背景 |
| `done` | `#42C98A` | 在线、完成、通过 |
| `working` | `#F2BE4C` | 运行中、等待用户、待装机 |
| `error` | `#F06B68` | 失败、失联、需处理告警 |
| `info` | `#76A9E8` | 链接、只读、待验收、来源跳转 |

颜色语义必须同时有文字/图标/形状提示；不能只依赖红黄绿颜色区分状态。浅色主题可在后续复用同一语义 token，但本轮原型以深色主主题为准。

### 5.2 字号与字重

字体优先使用系统无衬线：`-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif`；路径、ID、模型名、端口和数字使用等宽字体。

| 层级 | 字号/行高 | 字重 | 用途 |
|---|---|---|---|
| 页面标题 | 18px / 26px | 700 | 域标题、详情主标题 |
| 实体标题 | 15px / 22px | 650 | 会话/团队/项目名 |
| 正文 | 13px / 20px | 400 | 消息、卡片主体 |
| 重要正文 | 13px / 20px | 600 | 行动项、状态标题、主按钮 |
| 元信息 | 11px / 16px | 400 | 路径、时间、模型、来源 |
| 辅助标签 | 10px / 14px | 600 | badge、分组头、状态 chip |
| 数字/路径 | 11px / 16px 等宽 | 500 | 上下文、端口、版本、计数 |

禁止用大号标题制造营销感；cc-deck 是操作台，层级依靠字号、颜色、间距和位置共同表达。

### 5.3 密度与几何参数

| 参数 | 桌面基准 | 手机基准 |
|---|---:|---:|
| 设计基准视口 | 1440 × 900 | 390 × 844 |
| 域栏宽度 | 72px | 底栏 64px + safe area |
| 行动队列宽度 | 296px（可缩至 248px） | root 内容全宽，左右 16px |
| 证据检查器宽度 | 320px（可收起） | 半屏 sheet 或详情分段，不常驻 |
| 主区最小可用宽度 | 560px | 358px 内容宽 |

### 5.4 质感与动效

- 质感克制：深色实底、弱边框、局部渐变只用于主动作或等待状态；不使用大面积玻璃和强阴影。
- 选中态：暖橙 2px 线、暖橙弱底、标题提亮三者最多使用两项，避免整栏泛橙。
- 状态变化：新行动项从队列顶部轻量滑入；队列更新不闪烁；详情跨域使用 180—240ms 横向过渡。
- 动效可关闭；关闭后仍保留明确的静态选中和状态结果。

## 7. 原型验收清单

- 桌面模式能在会话、团队、项目、通知、设置五个工作面之间切换，域栏选中态与主区同步。
- 会话第二栏可在「行动队列 / 全部会话」切换；全部会话按项目分组，且不丢行动 badge。
- 队列卡选中后，主区标题、状态、详情和检查器发生联动。
- 等待卡点击“允许一次”后原地变为“已允许”，不会跳页或丢上下文。
- 手机模式有待处理收件箱、会话详情、团队待办与看板、项目和设置；进入会话详情后底栏隐藏，返回回来源页。
- 桌面与手机都能看到 `0.6.0-test.19 出包`、`ui-review 走查`、`cc-deck M1 攻坚团` 等真实语境数据。
