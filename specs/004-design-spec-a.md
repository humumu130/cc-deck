# cc-deck A 方向完整设计规范

版本：A / Command Bridge · 004-pre → 004（2026-10-05 收口）
输入：`specs/002-redesign-proposals.md`、`specs/003-redesign-sketches.html`、`specs/001-ia-freeze.md` 及现有功能基线。  
设计目标：把 cc-deck 做成面向行动的指挥桥——左侧看全局，第二栏决定先做什么，主工作区执行，右侧检查证据。

## 1. 设计决议

### 1.1 主心智

cc-deck 的首要问题不是“我有哪些页面”，而是“现在有哪些事情需要我处理，以及我如何确认它已经完成”。因此默认工作面以行动优先，但不得牺牲传统会话浏览：

- 桌面与手机会话列表采用同一条行动优先单流：`待处理` 组置顶，`其他会话` 组随后；两组互斥，其他会话可按项目继续分组。005 已核对一致（2026-10-05 双口径）。
- 桌面搜索、源可见性和后续状态/项目筛选归入列表工具行；手机不保留独立 `mobile-switch`。005 已核对结构一致；筛选按钮仍为演示占位，见收口偏差附录。
- 详情返回应恢复来源滚动位置；005 当前尚未保存/恢复该位置，列为修复批欠账。手机点击会话进入全屏详情，详情页隐藏底栏。

### 1.2 四层结构

| 层级 | 责任 | 桌面形态 | 手机对应 |
|---|---|---|---|
| 域栏 Domain Rail | 切换一级工作域、通知入口 | 左侧固定窄栏；会话入口使用 chat icon | 底部四 Tab；通知在 root 顶栏铃铛 |
| 行动队列 Action Queue | 当前域的优先级、筛选、实体入口 | 域栏右侧固定第二栏 | root 首屏的列表/卡片；不常驻于详情 |
| 主工作区 Main Workspace | 当前实体的核心内容与主动作 | 中央可滚动主区 | 单列全屏详情或 root 内容 |
| 证据检查器 Evidence Inspector | 任务、状态、用量、成员、产物和来源证据 | 右侧可收起检查器 | 详情内分段、半屏 sheet 或底部动作区 |

四层不是四个必须同时可见的面板：桌面宽屏（1440 基准）默认全显；视口宽度小于 1280px 时检查器默认收起为贴边窄条，主区自动占满让出的宽度；视口小于 920px 时行动队列再转为可展开抽屉；手机永远采用单列深入。

## 2. 信息架构定稿

### 2.1 域栏最终清单

域栏从上到下固定如下：

1. **会话**：默认启动域；承载行动优先单流、会话详情。
2. **团队**：承载团队列表、团队作战室、成员、派单、任务板和确认卡。
3. **项目**：承载按目录聚合的只读项目观测台。
4. **弹性空位**：视觉分隔，不承载未来功能占位。
5. **通知铃铛**：跨域行动入口；badge 只计需用户行动的 alert，不是消息未读数。
6. **设置**：承载连接与设备、配对、Agent 引擎、显示/快捷键、身份模板、扩展、关于。

域栏底部工具固定为“通知 → 设置 → 主题”；会话入口使用 `#icon-chat`，不使用 home 语义图标。主题切换留在 rail，深色显示太阳、浅色显示月亮；005 已核对图标切换、顺序和 18px 视觉框一致，月亮厚度仍列入浏览器目验。

连接状态不占用 rail 项位：由窗口顶栏/手机源栏旁的连接胶囊承担。胶囊显示当前源健康状态；点击后可查看各源状态、重连异常源或进入设置管理连接。

域栏选中态只允许一个内容域。通知面板是工具态，不覆盖当前域的选中态；连接快览同理。

### 2.2 行动队列的域映射

| 当前域 | 第二栏标题 | 默认分组 | 卡片必须显示 | 主动作倾向 |
|---|---|---|---|---|
| 会话 | 待我处理 | 待处理、其他会话（可按项目分组） | 会话名、项目、状态点、等待原因/摘要、最近活动、上下文水位、引擎徽章、源标签 | 打开会话、去任务/验收、恢复会话 |
| 团队 | 团队行动 | 待确认、进行中、待验收、已归档 | 团队名、成员数、任务进度、待处理数量、最近活动；成员/任务显示引擎，团队标题保留唯一源 | 打开团队、确认编制、进入看板 |
| 项目 | 项目观测 | 活跃项目、存在风险、已隐藏 | 目录、会话数、团队数、输出物数、需行动数 | 查看聚合、跳原始域 |
| 通知 | 需你行动 | 需你行动、注意、动态 | alert 标题、来源域、发生时间、行动标签、出处引擎/源 | 立即处理、跳原始来源 |
| 设置 | 设置导航 | 连接与设备、Agent 引擎、偏好、团队身份、扩展、关于 | 分组标题、当前状态、异常提示 | 打开设置子页 |

### 2.3 主工作区与证据检查器

- 主工作区同一时刻只服务一个“当前实体”。队列卡选中后，主区标题、状态、段签和检查器必须同步更新。
- 主工作区顶部固定实体标题、来源/路径、状态标签和局部段签；主内容区可滚动；主动作不随长内容消失。
- 第三列 head 只保留实体标题、身份、路径/工作目录、最近活动和当前状态标签；005 已核对旧 `.session-state-row`/`.status-note` 不再存在，但桌面 `#session-status` 与手机详情 head 的状态 tag 仍保留，属于当前实施口径，不能写成“head 完全无状态”。对话 pane 与 composer 之间保留唯一 `.session-state-dock`：任务段显示当前任务摘要，活动段在有操作时显示状态词、操作和耗时；dock 不放行动按钮，具体授权只在 `wait-card`。done 收起尚无自动逻辑，error 保留规则符合；收起时机列为修复批欠账。
- 证据检查器默认显示当前实体最重要的 3—5 项证据，不做信息仓库。超出部分进入“查看全部”或对应段签。
- 检查器可收起；收起后保留一枚可见的“证据”按钮和待处理数量，不得让用户失去当前风险提示。
- 项目域检查器显示来源链路和聚合计数，不出现编辑按钮；所有写操作按钮文案必须明确“在会话中处理”或“在团队中处理”。

## 3. 各域关键屏与状态口径

状态口径统一为：正常态展示真实数据；空态解释为什么为空并给下一步；加载态保留结构不跳动；错误态说明影响范围并给最小恢复动作。原型演示载体（#58）：`?demo=empty|loading|error` URL 参数进入对应演示态（壳角显示演示徽标防混淆），无参数=正常演示流；各态文案以本节各域表格为准，一字不改。

### 3.1 会话域

**关键屏：行动驾驶舱、全部会话浏览、会话详情。**

| 状态 | 行动队列/主区表现 | 用户下一步 |
|---|---|---|---|
| 正常态 | 「待处理」组默认置顶，随后为互斥的「其他会话」组；其他会话可按项目分组显示 `cc-deck`、`windclaw-qclaw` 等项目；详情显示对话、任务、输出物、用量、等待卡和附件 | 点击队列卡进入详情；点击局部段签定位内容；主动作固定在输入/动作栏 |
| 空态 | 无行动项时显示“暂无待你处理”，下方保留「全部会话」入口；无任何会话时显示“还没有会话”与「新建会话」 | 切到全部会话、刷新、创建会话或去设置配对 |
| 加载态 | 队列保留三组骨架卡；主区保留标题骨架、时间线骨架和检查器骨架；不把已有内容整体清空 | 用户可以返回或切换域；禁止对未加载卡执行动作 |
| 错误态 | 队列顶部显示连接/事件流异常；缓存数据降级为只读并标记“数据可能过期”；主区显示最后更新时间 | 「重连」「打开连接设置」；重连成功后原位置恢复 |

会话详情局部段签固定顺序：`对话`、`任务`、`输出物`、`用量`；低频的定时任务、全部日志、权限细节预留在 `⋯`。005 保留 `⋯` 视觉入口但尚未提供菜单内容或待处理数量承载，当前按只读/占位处理，列入收口偏差附录。

底部 composer 常驻可输入，Enter/发送按钮即时入列（用户气泡）并提示回执等待；附件/图片为占位动作。AI、PM、Worker 等非用户消息统一为头像/名称/角色行 + 无框正文，正文使用 pane 可用宽度；用户消息保留中性气泡。手机详情 head 副标题拆「路径 + 最近活动时间」两级（#63 修复批）：时间完整保留不截断（flex 不收缩），路径可截短或省略；不允许时间文本被路径挤到截断。

### 3.2 团队域

**关键屏：团队行动队列、团队作战室、成员/派单/确认检查器。**

| 状态 | 行动队列/主区表现 | 用户下一步 |
|---|---|---|
| 正常态 | 队列按待确认、进行中、待审查、已归档分组；主区默认团队看板，显示待认领、进行中、待审查、待收单、完成五泳道（泳道词表 2026-10-05 拍板：submitted=待审查、ready_to_install=待收单；分区/段数是渲染层自由，空泳道按 workflow_profile 门控属实装层行为，静态原型五列全显）；检查器显示成员和派单证据 | 开团、确认编制、拖动/改派任务、打开成员、填写/确认验收单 |
| 空态 | 无团队时显示开团四步说明；无行动时显示“团队运行正常”；归档为空不报错 | 「新建团队」「查看已归档」 |
| 加载态 | 团队卡、泳道列和成员行使用固定高度骨架；保留团队标题和连接状态 | 等待快照；可切换域但不对骨架操作 |
| 错误态 | 如果事件流断开，主区保留最近快照并显示“只读/更新时间”；如果单个成员失联，标红成员并保留接替入口 | 重连、换厂商接替、打开连接设置；不得误报为整个团队失败 |

团队详情段签顺序：`对话`、`看板`、`成员`、`活动`。对话只留目标、范围和决策；认领、提交、停滞等动静进入看板/活动。AI/PM/Worker 消息使用无框正文；用户消息在团队第三列沿用对话时间线左对齐覆盖，而不是个人会话的右对齐气泡。该差异为 005 当前实施口径，是否转为统一右对齐列为用户拍板项。对话 tab 的输入栏恒贴底常驻（#62-A）：气泡区独立滚动，输入栏随对话 pane 纵向 flex 钉在底部，视觉语言对齐会话域 footer（上边框+底色填充+上投影）；内容多少、tab 切换重建均不改变其贴底位置。

### 3.3 项目域

**关键屏：项目观测台、项目详情四分节。**

| 状态 | 行动队列/主区表现 | 用户下一步 |
|---|---|---|
| 正常态 | 按目录聚合会话、团队、输出物、验收单；四项统计使用一条轻量指标带，聚合入口使用列表行；主区显示路径、活跃数、风险数和只读标识；检查器显示来源链路 | 查看聚合、跳到原始会话/团队、打开输出物或验收来源 |
| 空态 | 未发现项目时说明“按目录自动识别”，提供「打开目录」或「刷新扫描」；无风险时明确“暂无需行动” | 打开目录、刷新扫描、回会话域新建会话 |
| 加载态 | 项目列表保留目录行骨架，主区保留四分节骨架；扫描中显示进度而不是空白 | 等待扫描；允许离开并在后台完成 |
| 错误态 | 目录不可访问、realpath 失效或聚合源异常时，标记具体项目/来源，不把整个项目列表置红 | 「重新扫描」「在会话中查看来源」；项目域本身不提供修复写操作 |

项目四分节固定为：`会话`、`团队`、`输出物`、`验收单`。它们是只读聚合视图，不是四套新的编辑面。指标带使用“语义词 + 数字”，会话/团队/输出物可使用 chat/users/package 类实体 icon；需行动、运行中、待验收等状态计数不加 icon。

只读语义按「一处状态 + 一处说明 + 一句短提示」三层收口（#63 修复批拍板）：head 保留短状态徽标「只读聚合」；中央保留一处完整说明（编辑请回到来源会话或团队）；底部 footer 只留一句短提示（「编辑请回来源域」量级）；聚合区标题、验收 pane、水位等处不再重复「只读」字样，桌面全文出现不超过 2 次。移动端同规则：顶部状态位 + 一处操作说明，副标题与聚合区标题去重。只读详情页不得出现看似可写的入口（如无说明的「+」按钮）；新建类动作只放回项目列表上下文。

### 3.4 设置域

**关键屏：设置导航、连接与设备、Agent 引擎、偏好/身份/扩展。**

| 状态 | 行动队列/主区表现 | 用户下一步 |
|---|---|---|
| 正常态 | 第二栏显示设置分组和异常提示；主区显示当前设置页；检查器显示当前连接、凭证存储边界和同步状态 | 编辑连接、验证引擎连接、调整偏好、查看身份模板/扩展 |
| 空态 | 未配置 relay/设备时显示“尚未配对”，提供配对码/扫码入口；未登记 provider 时说明默认继承本机环境 | 配对设备、添加连接、回电脑/网页录入凭证 |
| 加载态 | 服务器、设备、provider 行显示骨架；保留设置标题和返回位置 | 等待读取；不可提交未完成表单 |
| 错误态 | 按连接、设备、provider 分项报错；表单保留用户已填值；不把单个设备错误扩散为全局离线 | 重试、重配对、换路由、打开帮助；显示最后成功时间 |

设置子页建议：`通用`、`Agent 引擎`、`连接与设备`、`团队身份模板`、`扩展`、`关于`。手机为浏览/验证/换路由优先，凭证录入回电脑或网页端。左栏分组名与子页名不重复（#63 修复批）：分组用上位词「连接管理」，子页仍叫「连接与设备」；手机设置同分组口径。

### 3.5 通知域

**关键屏：通知面板、来源摘要与跳转卡。**

| 状态 | 行动队列/主区表现 | 用户下一步 |
|---|---|---|
| 正常态 | 队列分需你行动、注意、动态；badge 只取第一组；主区展示“谁/什么事/等什么”的来源摘要卡；检查器显示来源实体与写面归属 | 轻动作内联完成；重流程跳原始来源域 |
| 空态 | 显示“暂无需要你行动的通知”；可切看历史动态但不伪造 badge | 回当前域或查看动态历史 |
| 加载态 | 按分组显示通知骨架；保留铃铛标题和当前域上下文 | 等待事件流；不因加载自动清零 |
| 错误态 | 显示“通知可能未同步”和最后同步时间；已缓存 alert 保留红色风险标识 | 重试同步、打开连接设置；不把缓存 alert 静默隐藏 |

通知域采用 B+：重流程只展示来源摘要与跳转卡，不嵌入验收表单或第二写面；验收回填/确认收单回会话域，失联接替/编制确认回团队域，项目域只读聚合。轻动作白名单仅包含“标记已读、暂停提醒、确认已知”，在通知域内幂等完成。通知卡正文用「谁 / 什么事 / 等什么」三段标签-值结构，各占独立行（标签小号灰字、值正常字重、实体名加粗），不压成一条连续长句（#63 修复批，桌面通知卡与手机通知卡同构）。

轻动作判定写死为“单一、幂等、无表单、可安全重试”；涉及证据填写、成员选择、确认卡、多实体变更或不可逆的动作均为重流程，必须跳来源域。通知卡跳转携带 `sourceContext`：至少包含 `domain`、`entityId`、`segment`、`alertId`、`returnPath` 五字段；桌面回原域段签，手机来源详情返回通知中心而非默认会话首页。

侧栏摘要卡整卡可点并跳来源域；主区详情卡仅按钮跳转（多目标分叉不做整卡点按）；历史动态点击仅提示已归档。

通知 badge 沿用 `specs/001-ia-freeze.md`：只计 active、需用户行动的 alert；普通动态、warning/info、任务完成汇报不计入；打开面板不自动清零，执行轻动作或明确处理后清零，处理完最后一项行动项时 rail 铃铛 badge 与通知域计数同步归零。

## 4. 交互规则

### 4.1 跨域跳转与来源返回栈

#### 跳转模型

- 域栏切换是一级切换，不等同于返回；每个域应保存最近队列筛选、选中实体和滚动位置。005 当前仅保留选中实体/来源返回结构，详情返回的列表滚动位置尚未保存/恢复，作为收口欠账，见附录。
- 项目聚合卡、通知 alert、验收单入口必须携带 `sourceContext`：来源域、来源详情、来源滚动锚点、来源子视图。
- 写操作只在原始域执行：项目卡的“查看会话/团队”与通知的“去处理”都是带来源上下文的跳转。
- 桌面 URL/history 至少恢复域、实体、局部段签；刷新后按域 → 详情 → 段签顺序恢复。

#### 返回优先级

1. 先关闭当前弹窗、sheet、通知面板、连接快览或检查器浮层。
2. 处于详情时回 `sourceContext`，不能无条件回会话首页。
3. 从项目跳到会话/团队，返回项目详情并恢复原项目滚动位置。
4. 从通知摘要跳到原始处理页，返回通知中心；再次返回才回进入通知前的域。手机来源详情的显式返回文案为“返回通知中心”。
5. 已在 root 时，桌面交给 history，手机回上一个 root 或执行系统退出。

动画期间的返回动作不能被静默吞掉；进入/退出动画完成后必须恢复可消费状态。

### 4.2 局部视图段签

- 段签只描述当前实体的内容切片，不承担一级域切换。
- 默认段签只放高频 3—4 项；低频能力进入 `⋯`，菜单标题必须带出待处理数量。005 当前保留 `⋯` 入口视觉位但未实现菜单内容，未满足待处理数量承载，作为欠账，不以静态占位冒充可用菜单。
- 段签顺序跨端一致，桌面可横排，手机可横滑；当前段签用底部 2px 暖橙线和高亮文字，不用大面积橙底。
- 点击任务引用、输出物、验收卡时，先切到对应段签，再定位到具体行；找不到历史行时只切段签，不弹错误。
- 段签切换不改变来源返回栈；桌面同步 history，手机保留页面内部状态。
- 段签实现 WAI-ARIA tabs 键盘语义（#58 产品化批条目 5）：段签容器 `role=tablist`，每个段签 `role=tab` 且 `aria-controls` 指向面板 id，面板 `role=tabpanel` 且 `aria-labelledby` 回指；`aria-selected` 与 roving tabIndex（激活 0、其余 -1）随激活态同步；tablist 内左右方向键循环切换前后段签并焦点跟随到新激活段签；桌面 segment-bar 与手机 mobile-detail-tabs（会话详情、团队页）共用同一套接线，覆盖全部段签容器。

### 4.3 主动作固定位置

- 会话：输入/附件/发送固定主工作区底部；等待卡的“允许一次/拒绝并说明”固定在等待卡内部，避免用户滚到底部找审批。
- composer 动作层级（#63 修复批拍板，桌面会话域与手机详情同一家族规则）：空输入时发送按钮为禁用态（降对比/描边中性，不可点）；有有效内容恢复可用。等待卡可见期间「允许一次」保持最高强调（橙实心），发送按钮即使可用也降一档（次级描边/降饱和底），同一屏不得出现两个橙实心主按钮；等待卡消费（允许/拒绝）后发送按钮恢复普通主样式。
- 团队：开团、确认编制、派单、接替固定在当前团队/成员检查器底部；看板卡上的主动作不超过一个。
- 项目：不出现“保存/编辑/确认”主按钮；只允许“查看来源”“在会话中处理”“在团队中处理”。
- 通知：主区只提供来源摘要卡与轻动作；重流程按钮跳来源域，不在通知域出现验收表单。验收来源域仍在当前工作区底部固定“提交回填/确认收单”。
- 设置：表单页底部固定保存/验证；连接页的重配对/踢出按设备行就近放置，危险动作二次确认。
- 手机详情：主动作随底部输入栏/动作栏固定；全局底栏隐藏，避免两个底部动作层叠。

### 4.4 队列行为

- 队列卡点击即选中并联动主区/检查器；单击不直接执行危险动作。
- 会话域第二栏改为单滚动流：`待处理` 组置顶、`其他会话` 组随后，两组互斥；其他会话可按项目分组。桌面工具行承载搜索、源可见性和筛选入口，手机不再保留独立切换器。005 已核对单流、互斥、分组和计数一致；筛选按钮当前为演示占位。
- 组头计数等于当前实际渲染/可见卡数；源过滤隐藏卡时，列表尾可显示“查看全部 N 个会话”的承接入口，不造假卡。
- 队列更新时只更新受影响卡片；规范目标是不因事件刷新跳回顶部，但 005 详情返回恢复滚动位置尚未实现，列为修复批欠账。

### 4.4.1 计数口径三态（#63 修复批拍板）

- 分组头与角标计数必须与实际渲染内容自洽，表达按三态收口：内容完整呈现时写 `语义词 · 数字`（如「运行中 · 2」）；总数大于可见数（滚动/折叠/截断）才用 `已显示 2/4`；业务计数一律带语义词（「需行动 2」），**禁止裸数字角标**。005 的项目指标已采用该顺序；源切换器仍有“6 会话 · 2 行动”、通知头仍有“2 项需行动”等历史语序残留，按实施记录于附录。
- 全部会话按项目分组时，项目名旁计数 = 该项目实际渲染卡数（「cc-deck · 4 个会话」）。
- 手机「待处理」= 只放需要用户动作的卡；运行态卡归顶部统计的「运行中」分位，不混入待处理列表，副标题计数与列表卡数全等（「3 个行动项」对应 3 张行动卡）。
- 团队页/泳道分组计数同理：分组头数字 = 分组内实际卡数（「待收单 · 1」；词表 2026-10-05 拍板，旧词「就绪待装机」退役）。
- 原型静态演示数据同样执行本口径：宁可改计数，不伪造多余卡片。

### 4.5 检查器收起行为

- 检查器默认可见，标题行提供收起/展开按钮；收起后保留 42px 贴边窄条和证据图标，主工作区自动占满释放的 278px。
- 视口宽度 `<1280px` 时强制收起检查器；窄窗点击展开只提示“窗口过窄，暂时无法展开检查器”，不改变布局。宽窗（`≥1280px`）才允许手动收/展，并记录 `collapsed/expanded` 偏好；跨断点后按该偏好恢复，未手动操作过则自动展开。
- 视口宽度 `<920px` 时，行动队列转为抽屉入口；检查器不与行动队列同时覆盖主区，避免两层抽屉叠加。
- 收起/展开不改变当前实体、段签、滚动位置或来源返回栈；前三栏中的行动队列与主工作区宽度保持不变，释放的 278px 从整个桌面面板宽度扣除，过渡时长 180ms。
- Tauri 桌面端：用户手动收起时窗口 `setSize` 缩窄一次；之后用户拖拽窗口尊重用户宽度。断点自动收起只做内部重排，不因“放不下”反缩用户窗口。这是紧凑常驻窗的拍板语义，不采用 VS Code 内容区吸收模式。
- 手机不显示常驻检查器；证据以段签、半屏 sheet 或详情内联卡承载。

### 4.5.1 水位可见性

- 任一域的第三栏都必须保留相关实体的上下文水位：会话显示完整分段用量组件；团队成员与派单检查器显示成员级迷你水位；通知显示当前来源会话水位；项目显示最活跃会话水位。
- 水位只表达态势感知，不产生第二写面；统一使用 `ctx-safe / ctx-attention / ctx-critical` 三档及 `ctx-track` 轨道色，条高不超过 6px。成员级迷你水位将百分比与负载词合并为同一行（如 `64% · 充足`），避免窄卡竖排或压住引擎徽章；额度走尽或失联成员必须落到 critical 红档。
- 域切换不能让水位信息消失；手机端在详情或来源上下文内联显示同一口径，避免仅桌面可见。

### 4.6 输出物目录与下载

- 会话详情「输出物」段签采用“摘要 → 目录组 → 散文件”三层：同父目录至少 2 个文件才成组，单文件目录保持散行；最近活跃组默认展开，其余收起。
- 目录组头固定显示目录名、文件数、总大小/最近时间和组级「批量下载」；行尾 `⋯` 仅提供展开/收起、复制路径、打开目录。打开目录只对本机源成立，远程源必须明确提示而不是伪造路径。目录组去阴影、去大面积底色和完整圆角卡框，使用弱分隔线/左侧引导线；文件项保持列表行。005 已核对一致。
- 批量下载只允许组内全选，状态必须可见地经过“排队 → 进行中（进度）→ 部分失败（失败项/重试）→ 完成”；命名冲突自动递增并在完成态说明。手机目录组头改用 action sheet，提供“下载目录全部/下载单个文件”。
- 项目域「输出物」按“源 → 目录组”只读聚合，只提供“查看来源会话”；来源不可达按源显示错误，不把整项目染红，不复制本机打开目录动作。
- 空态显示“当前会话还没有输出物”；加载态保留摘要与目录骨架；部分失败和远程不可达必须保留已知目录索引并标明失败原因。

### 4.6.1 上下文用量组件

- 会话详情的桌面检查器「用量」块与手机详情「用量」段签使用同一组件，不再使用单条普通进度条或只写“上下文”三个字的水位条。005 将 meter 压为轻量 `usage-summary`，保留数字、百分比、模型和安全提示；活动记录采用时间线列表行。
- 组件固定展示四项信息：当前模型、已用 token、上下限、百分比；视觉结构为 `Context window` 小标题 + 模型/上限副标题 + 12 段色带 + `84k / 200k tokens` 双数字 + 百分比。
- 紧张度按原始占用比判级：`<60%` 为「安全」使用 `ctx-safe`，`60%—<85%` 为「偏高」使用 `ctx-attention`，`≥85%` 为「将满」使用 `ctx-critical`。色带、百分比和状态胶囊必须同步换色，并保留文字判级，不能只依赖颜色。
- 色带按 12 段表达大致占用，不要求精确到每个 token；精确值以双数字和百分比为准。缺少上限或数据加载时显示骨架/“等待 relay 数据”，异常时显示“用量暂不可用”而不是伪造 0%。
- 桌面检查器采用紧凑卡片；手机使用详情内联卡，保持同样的信息顺序，不能退化为旧式大水位条。

### 4.6.2 IA 拍板补记

- rail 不设连接图标与品牌块（方案 A 用户拍板 2026-10-04）；一级入口首项为会话，连接状态由全局连接胶囊承担。

### 4.7 多源全局层

- **桌面位置**：放在窗口顶栏、`Command Bridge` 标题旁；**手机位置**：每个 root 顶栏的状态栏下方，以“状态点+源名”的轻量 sourcebar/源胶囊呈现。sourcebar 透明、约 28–30px，不与 root head 使用同级背景、边框或阴影；在线时隐藏重复连接文案，异常/重连时才展开状态文案。点击胶囊展开下拉/小型 sheet，不依赖含糊的更多菜单。
- 源切换器旁增加独立的**连接胶囊**：源切换器负责选择当前源/进入聚合，连接胶囊只负责当前健康状态、异常源最小恢复和进入连接管理，不把两种动作混成一个控件。桌面胶囊高度约 `28px`；手机为同一组件的压缩版。
- 单源时连接胶囊只显示状态点 + “已连接/重连中/已断开”，不重复当前源名；聚合时显示汇总“2 源 · 1 异常”或“2 源 · 全部正常”。汇总状态取红优先于黄、黄优先于绿，但 popover 内逐源保留真实状态，不能用汇总色遮蔽异常源。
- 胶囊 popover 逐行显示源名、三态和可选延迟；重连中/断开源同一行提供“重连”最小动作；底部“管理连接…”直达设置→连接与设备。深度验证、换路由、配对仍只在设置完成。
- 源列表至少包含全部已连 relay（如「公司电脑」「家里 iMac」），每项显示状态与计数；点击源项切换当前源，底部固定入口为「管理与配对新源」，进入设置→连接与设备。
- 源切换器内提供 `单源 / 多源聚合` 段签。单源为默认，保持现版只看当前 relay；聚合将各源事件合流，行动队列和全部会话可按源分组，聚合态强制显示卡片源标签。
- 聚合态主标签按 005 当前实施使用“多源聚合”标识；项目输出物按“源 → 目录组”保留公司电脑/家里 iMac 的独立源副本、可达性和不可达恢复入口。手机项目输出物沿用源模式与目录内容，但当前没有桌面 `source-group-bar` 同构的手机源分组头，列为实施偏差。
- 会话列表卡在单源模式不展示源徽标（源已唯一，避免重复噪声）；切换到多源聚合后恢复展示，用于区分公司电脑与家里 iMac。
- 单源过滤承接（#58）：当前激活视图存在被源过滤隐藏的卡（N>0）时，列表尾显示承接入口「已按当前源过滤 · 查看全部 N」，点击切换多源聚合；N=当前视图实际隐藏卡数（激活视图口径，非全容器）；聚合态或 N=0 时不出现。手机收件箱同款。留白由入口承接，不造假卡填充。
- 手机进入聚合：源胶囊 → 选择「多源聚合」；退出聚合：同一胶囊 → 选择某一源或「单源」。聚合态收件箱在首屏源分组条显示「公司电脑 / 家里 iMac」，卡片保留源色标签；切换源后连接状态点随当前源更新。
- **badge 口径**：聚合模式下 badge = 各源「需你行动」数量之和；同一事件以稳定 `alert_id` 去重，跨源 `alert_id` 的统一规则待后端事件协议冻结前标注为待定，不用标题或时间猜测去重。
- 连接胶囊只表示**当前源**或聚合态的连接健康信号；源切换器负责选择/聚合/计数，设置→连接与设备负责配对、重命名、移除、认证。连接胶囊不代替源管理入口。
- 弹层键盘关闭（#58 产品化批条目 5）：源菜单与连接 popover 打开时按 Esc 关闭（无弹层打开时不拦截 Esc，保留输入框等默认行为）；打开时焦点移入弹层首个可操作项，关闭后焦点归还对应触发按钮，触发按钮 `aria-expanded` 与开合状态全程同步。

### 4.8 全局反馈 Toast 壳层（#63 修复批拍板）

- Toast 锚定在**应用壳体内部**，不落在页面背景：桌面态锚 `.desktop-frame` 内右下角，手机态锚 `.mobile-frame` 内右下角，均带安全边距；手机侧底距需避开底部 Tab 与 composer（不遮、不被裁）。
- 所有触发源（域切换、单源/聚合切换、卡片密度切换等）共用同一锚点与样式；不允许一部分挂视口、一部分挂壳体。
- 桌面/手机模式切换时 Toast 宿主随之迁移（同一 showToast 入口按当前 stage 重新挂载），历史 Toast 不跨壳残留。
- Toast 不进布局流（绝对定位），壳体裁剪时优先调 z-index/边距，不允许把 Toast 移出壳体解决遮挡。

### 5.2 字号与字重

字体优先使用系统无衬线：`-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif`；路径、ID、模型名、端口和数字使用等宽字体。

| 层级 | 字号/行高 | 字重 | 用途 |
|---|---|---|---|
| 页面标题 | 18px / 26px | 700 | 域标题、详情主标题 |
| 实体标题 | 15px / 22px | 650 | 会话/团队/项目名 |
| 正文 | 13px / 20px | 400 | 消息、卡片主体 |
| 重要正文 | 13px / 20px | 600 | 行动项、状态标题、主按钮 |
| 元信息 | 11px / 16px | 400 | 路径、时间、模型、来源 |
| 辅助标签 | 10px / 14px | 600 | badge、分组头、状态 chip |
| 数字/路径 | 11px / 16px 等宽 | 500 | 上下文、端口、版本、计数 |

辅助信息的最小字号为 `10px`；仅 `Context window` kicker 允许使用 `9px`，避免在桌面高密度区和手机窄屏出现不可读的微型文字。

禁止用大号标题制造营销感；cc-deck 是操作台，层级依靠字号、颜色、间距和位置共同表达。

### 5.4 质感与动效

- 质感克制：深色实底、弱边框、局部渐变只用于主动作或等待状态；不使用大面积玻璃和强阴影。主区、行动队列、检查器使用相邻但可辨的深蓝层级，卡片使用轻阴影而非浮夸发光。
- 选中态：使用中性亮描边/左指示条/轻底（`selected-line`、`selected-bg`），brand 不再承担选中语义；brand 只保留主 CTA 与段签下划线。
- 语义色收敛：`brand` 只承担品牌与主 CTA；选中态使用中性描边/左指示条。待办/待确认标签可用橙系，失联、断开、错误类标签统一使用 `danger/error`，不在同一实体上用橙色掩盖红色故障。
- 进度与气泡：普通进度条使用中性 `progress-fill`；只有占用率达到 `80%` 才切换 `ctx-critical`。AI、PM、Worker 等非用户消息使用头像行+无框正文；用户气泡使用中性面与方向/边框区分，不复用品牌橙底。wait-card、确认卡、错误卡属于行动/风险组件，可保留块状形态；005 当前仅有 wait-card 明确实现，错误/确认卡完备性列入补验。
- 重复信息：常驻检查器可以保留摘要；详情「用量」段签只显示轻量数字、分档和“在检查器查看”提示，不复制完整上下文组件。005 已将 `status-note` 并入状态 dock；状态 dock 任务段承载稳定任务摘要，活动段承载有操作时的状态词/操作/耗时，不提供授权按钮。
- 组件 token：卡片圆角 `10px`（手机 `12px`）、控件圆角 `7px`（手机 `9px`）、卡片描边 `1px line`、卡片内边距 `12px`；状态点 `7px`，状态 chip 与引擎徽章使用胶囊，源标签使用 `5px` 方角。
- 状态变化：新行动项从队列顶部轻量滑入；队列更新不闪烁；屏切换、队列选中、检查器收起/展开和 toast 使用 `180ms ease`，详情跨域使用 `180—240ms` 横向过渡。
- 主按钮使用暖橙渐变和极弱内高光；次级按钮仅改变底色/描边，危险按钮只保留低饱和红色边界，不使用大面积警示色。
- 主行动按钮和“允许一次”使用 `brand-strong`；引擎徽章与源标签统一中性浅底描边，彩色只承担状态/行动语义。手机通知轻动作使用 ghost 描边并保持 44px 触控热区。
- 滚动条使用低对比度蓝灰轨道和圆角 thumb；hover 仅提高对比度，不改变布局。焦点使用 `brand-hover` 外描边。
- 手机触控热区：确认/拒绝、重连等核心动作最小 `44px` 高；连接胶囊与铃铛视觉尺寸不变，用透明外扩热区达到 `44px`，不额外挤占顶栏布局。
- 连接胶囊为“状态点 + 已连接/重连中/已断开”纯文字状态，不重复当前源名；源名只由源切换器承担，三态颜色仍沿用 `done/working/error`。
- 动效可关闭；关闭后仍保留明确的静态选中和状态结果。

### 5.4.2 卡片与列表行边界

- **卡片=可选择实体**：会话、任务、成员、输出物、验收单等异构对象，需要选中态、对比或风险强调时使用卡片。
- **列表行=导航/配置**：设置项、纯文本信息和操作入口使用图标+标题+副文案+状态/chevron 的紧凑行；选中态用 brand 左描边或浅底，不加完整卡片阴影。
- 通知采用轻量可选择行；检查器分区保持块状分组；项目总览四项数字使用无卡框指标带，项目会话/团队/输出物/验收单入口使用图标+标题+副文案+状态/chevron 的列表行；进入明细后回到列表行。
- 输出物源组、目录组和检查器子分区属于轻量分组块，保留分组线、触控头和局部风险态，不使用实体卡面；用量属于轻量状态摘要块，活动属于列表行；新建团队属于轻量创建按钮，不是实体卡。以上条款均已按 005 核对一致（2026-10-05 双口径）。
- 固定卡高下不留空槽（#63 修复批）：缺第三行元信息的卡补**真实**数据行（如「双端 · test 通道 · 待收单」）；确实无数据的用稀疏卡变体内容顶对齐，不造假 engine/源徽标填充；外层卡高保持同域统一。
- 窄卡（看板泳道/队列）身份与来源信息单行化：nowrap + ellipsis 词级截断，不换行叠高；来源+engine 等次要信息可合并为一条紧凑元数据行。紧凑密度档只压字号/间距/次要行，不改变结构行数与对齐基线，不出现词中硬截断。
- 新增内容必须先判断对象是否需要“选中/对比”；不能因为实现方便把整屏配置全部卡片化。
- 选中态统一口径（#58 产品化批条目 8）：列表卡（会话队列卡、通知卡、手机主卡）选中 = inset 2px `selected-line` 左条 + `selected-bg` 轻底，基础边框保持中性不抢视觉；列表行（设置导航、源菜单项）选中 = inset 3px `brand` 左条 + `selected-bg` 浅底；看板任务卡不做选中态（点击即打开详情），hover 仅提升边框/底色对比、无上浮与阴影，桌面手机一致。

### 5.4.1 主题切换

- 默认使用深色主题；桌面域栏在设置按钮下方提供主题切换按钮，手机设置 root 提供“主题”设置行。两处操作同一份主题状态，不新增一级导航。
- 切换是即时换肤：背景层、文字、边框、卡片阴影、状态色、引擎徽章和源标签必须同时切换，不能只替换背景。
- 用户手动选择优先于系统偏好，持久化键为 `cc-deck-theme`，值为 `dark` 或 `light`；原型使用 `localStorage`，生产实现可迁移到用户设置同步。
- 原型默认不跟随系统；实现备注可增加“跟随系统”，但系统变化不得覆盖用户已明确选择。没有存储值时固定落深色。
- 连接状态三态不因主题切换改变语义：已连接使用 `done`，重连中使用 `working`，断开使用 `error`；浅色值采用 5.1 的专用对比度。

### 5.5 引擎与源标识体系

卡片可以同时出现两个身份维度，但视觉权重固定为“引擎主、源次”；颜色优先于静态位置表达源归属：

- 统计表达统一使用“语义词 + 数字”；会话、团队、输出物可在独立指标带、摘要和聚合列表行使用 `chat/users/package` 类实体 icon；需行动、运行中、待验收等状态计数不加 icon；路径、副标题、通知正文和自然语言消息保持纯文字。
- 会话一级入口使用 chat icon，不使用 home icon；rail 底部工具固定为通知→设置→主题，三个 SVG 使用统一 18px 视觉框，主题仍留在 rail。005 已核对一致。

- **引擎徽章**：用“短名 + 色点/小形状”表达执行 Agent；出现在会话行动队列卡、全部会话卡、详情头部、团队成员卡、任务卡、通知卡和输出物出处。六家均使用同样的胶囊尺寸和字重，不使用品牌 Logo，不让某一家因图标复杂而喧宾夺主。
- **源标签**：多 relay 模式下显示用户自定义节点名，如 `公司电脑`、`家里 iMac`；源徽标使用可读文字配稳定填充色块，`公司电脑`使用绿系、`家里 iMac`使用蓝系，保持方角小标签。单源模式下会话列表卡默认隐藏，避免每张卡增加噪声；通知卡、团队任务卡、检查器等其他位置按各自身份规则处理。
- **复合身份行**：单源模式标准顺序为 `[引擎徽章] [源标签]`；聚合模式改为 `[源标签] [引擎徽章]`，通过顺序提示当前分组键。详情头部可以重复一次作为当前实体确认，不把源名塞进会话标题。
- **引擎与源的区分**：引擎徽标维持中性描边胶囊与引擎色点；源徽标改用公司绿系/家庭蓝系填充色块，深浅主题均需保证文字可读，不把两者做成同一种视觉语法。
- **会话卡密度（#62-B）**：紧凑、标准、宽松三档，默认标准；密度 token 化为固定外高（block-size）58 / 76 / 86px，会话域行动队列与全部会话共用；卡内为固定行槽（标准/宽松三行：标题行、摘要单行省略、身份行；紧凑两行，徽标与摘要并排、徽标贴右）。卡片外高不因摘要长短、行动 tag 有无、源徽标显示与否而改变；缺内容的行保留行槽。团队、项目、设置第二列卡共用卡高 token，通知卡使用独立 notice 高 token——跨域不强制同一绝对高度，统一的是密度命名与卡片语言（圆角、边框、hover/选中态、字号行高截断、卡间距）；「新建团队」按 005 当前实施降为底部轻量按钮，不再要求与普通卡同高。手机保持三行结构，宽松档同步增加间距。

源标签中性 token：`source-bg = rgba(143,157,177,.08)`、`source-line = rgba(143,157,177,.24)`、`source-text = #8F9DB1`；已命名源使用 5.1.1 的 `source-company*` / `source-home*` token。源标签字号比引擎徽章小一档、对比度低一档；源离线时只在源标签旁加状态点，不把整张会话卡染红。

同一源的色值必须在三处复用：源切换器当前源/列表、聚合分组头、卡片源标签；源名可改，但用户配置后的颜色保持稳定，不随卡片位置变化。团队域为单源实体，成员卡和任务卡不显示源标签；团队工作区标题保留唯一源标签。

**落位对照：** 会话卡显示引擎+源；会话详情头部显示当前引擎+源；团队成员卡显示成员引擎、团队标题显示唯一源；团队任务卡显示执行者引擎不重复源；通知卡和输出物行显示出处身份；项目只读聚合优先显示源分组，进入实体后再显示完整复合身份。

**徽标冗余边界（#61）：** 身份锚点由第二列列表卡与第三列详情 head 承担，其余位置不重复身份徽章——证据检查器（第四列）的证据行、项目聚合卡的逐产物行、团队任务卡执行者区不再出现 engine/source 徽章；会话与手机详情副标题不重复引擎名。单源模式下第三列详情 head、项目 head、手机详情 head 的源徽章隐藏，多源聚合恢复（沿 #59 机制）。保留独立信息价值的四处不动：通知卡 engine+source、项目输出物按源分组头、设置域 provider 行、输出物浏览器目录组头。

### 5.5.1 成员头像与身份标识

- 默认头像零配置生成：`stableHash(memberName || memberId) → 稳定色`，内容取角色图标或首字母；同一成员跨 relay、桌面、手机保持一致。普通成员不做照片级头像，优先字符+色块+引擎角标。
- 角色可用低成本字符区分：`W`=worker、`A`=架构师、`QA`=验收；角色不承担权限语义，缺少角色信息时回退首字母。
- 引擎角标复用 5.5 六家徽章 token，固定在头像右下角；引擎色只表达来源引擎，不表达健康状态。源仍用次级 `source-badge`，不可用整张头像染色替代。
- **PM 特殊化**：头像使用暖橙 brand 描边和星徽 `✦` 记号；005 当前取消圆形渐变/轨道环/双层光环，保留 8px 圆角矩形、brand 描边和引擎角标。团队成员列表/成员卡、对话流气泡、任务卡执行者三处必须一致。角色徽标文案用角色语义词（如「调度」），不与成员名重复（#63 修复批：当时显示名 Leader + 徽标「调度」，不出现「Leader+Leader」双标识；组织模型 v2（018 §9）后显示名迁移为 PM，徽标与视觉规格不变；静态 markup 与 tab 重建模板同步）。
- 覆盖优先级为「成员详情覆盖 > 团队身份模板覆盖 > 默认自动生成」。可覆盖项为 `emoji / 字符 / 颜色` 三选；图片上传只作为未来实现备注，不列入一期必做。
- 会话流中的「我」气泡沿用同一公式；用户未设置时使用指挥者身份模板，不另造一套个人头像规则。设置域提供「团队身份模板 / 头像与身份」最小入口。

## 7. 原型验收清单

- 桌面模式能在会话、团队、项目、通知、设置五个工作面之间切换，域栏选中态与主区同步。
- 会话第二栏采用「待处理 / 其他会话」互斥单流；其他会话按项目分组，且不丢行动 badge。

- 手机模式有待处理收件箱、会话详情、团队待办与看板、项目和设置；进入会话详情后底栏隐藏，返回回来源页。
