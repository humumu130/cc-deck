# cc-deck 从零重设计方向提案

提案日期：2026-10-03  
提案目的：不延续 v7.1 的页面骨架，从产品任务出发，为桌面 Web 与手机 Expo 重新选择信息架构、导航模型和视觉语言。本轮只供用户挑选方向，不进入完整规范或代码实现。

## 0. 共同设计底线

三个方向都必须覆盖同一套功能能力，不以“换模型”为理由删减功能：

| 能力面 | 必须承载的内容 |
|---|---|
| 会话 | 会话列表、详情对话流、任务清单、输出物、用量统计、审批/等待卡、图片与文件收发 |
| 团队 | 成员状态、派单、任务板、确认卡、Leader 协作与验收动作 |
| 项目 | 按目录聚合会话/团队/输出物/验收信息；只读聚合，写操作回原域 |
| 通知 | 只计需用户行动的 alert；进入后可跳回原始会话、团队或设置上下文 |
| 设置 | 连接状态、配对、设备、模型服务、显示/快捷键、团队身份模板、扩展、关于 |
| 验收 | 验收单查看、逐项回填、提交回填、确认收单；支持从会话/团队/项目/通知进入 |

共同交互原则：桌面可以保留多栏并行上下文，手机使用单列深入；详情页必须定义清楚来源和返回，不依赖“回到首页”兜底；项目域不得产生第二套可写实体。

---

## 方向 A：指挥桥 Command Bridge（推荐候选）

### 设计理念

**把 cc-deck 设计成一座面向行动的指挥桥：左侧看全局，中央做决策，右侧核对证据。**

### 信息架构与导航模型

#### 桌面 Web

- **全局导航：** 最左为窄型域栏：会话、团队、项目、设置；通知不占内容域，以独立行动铃铛挂在域栏下段；顶部连接状态是全局健康信号。
- **工作队列：** 第二栏不是静态“列表”，而是当前域的行动队列。会话域按“需我处理 / 运行中 / 最近完成”分组；团队域按“待确认 / 进行中 / 待验收”分组；项目域按目录和最近风险分组。
- **主工作区：** 中央是当前实体的主内容；右侧为可收起的证据/上下文检查器，承载任务、用量、成员、输出物、审批详情和验收单摘要。
- **层级：** 域 → 实体详情 → 局部视图。局部视图优先使用顶部段签或横向分段，动作尽量固定在主内容底部/右侧，不把所有能力塞进全局导航。
- **跨域跳转：** 项目和通知都保存来源上下文；从聚合卡点入会话/团队后，返回回到原聚合位置。

#### 手机 Expo

- **底栏四域：** 会话、团队、项目、设置；通知为所有 root 顶栏的铃铛入口，不占底栏。
- **会话 root：** 默认不是纯列表，而是“待处理优先”的收件箱；可切换到全部会话。点击后进入全屏详情，底部使用实体动作栏，不显示全局底栏。
- **团队 root：** 默认显示待确认/待验收卡，其下是成员和任务板入口；详情内以分段切换对话、看板、成员、活动。
- **项目 root：** 以只读项目卡和风险摘要为主，点击进入项目详情后按四个只读分节浏览，再跳回原始域。
- **返回：** 临时 sheet → 详情 → 来源页；手机 root 之间切换不堆入详情返回栈。

### 关键屏结构

#### 桌面屏 1：行动驾驶舱 / 会话域

- 左侧域栏：品牌标识、连接状态、四域图标、通知铃铛、个人/设置。
- 第二栏顶部：`待我处理 3`、搜索、过滤；下方为会话卡，卡上直接显示状态、上下文水位、等待原因和待处理标签。
- 中央：对话时间线；审批/等待卡、图片、文件、任务引用均以内嵌卡呈现；底部为输入与附件操作。
- 右侧检查器：任务完成度、用量统计、当前模型/权限、输出物目录；点击某项可定位中央内容。

#### 桌面屏 2：团队作战室

- 左栏列出团队和行动量；中间为任务板泳道：待认领、进行中、待验收、待装机、完成。
- 每张任务卡同时显示认领人、分支、上下文、最近日志、AI 自验和用户验收状态。
- 右侧检查器切换成员详情、派单记录、确认卡和验收单；派单与接替动作固定在成员/任务上下文中。

#### 桌面屏 3：项目观测台

- 顶部显示项目路径、活跃实体数、风险数和只读标识。
- 中央为项目关系视图：会话、团队、输出物、验收单四类卡按目录/时间聚合；每类卡只展示摘要和跳转。
- 右侧显示项目时间线、最近产物和待处理风险；所有操作按钮文案明确为“在会话中查看”或“在团队中处理”。

#### 桌面屏 4：行动通知与验收工作台

- 通知面板按需你行动、注意、动态分层，但 badge 只统计第一层。
- 点击行动项后右侧打开来源上下文，中央展示验收单或接替/配对处理表单；完成后原地更新 badge，不丢通知列表。

#### 手机屏 1：会话行动收件箱

- 顶栏显示当前连接、通知铃铛和搜索；首屏是待处理卡，其下是运行中/最近会话分区。
- 卡片直接露出“等待确认”“任务完成”“待验收”等下一动作，避免先进入详情再找原因。

#### 手机屏 2：会话详情

- 顶部返回、标题、状态和上下文水位；中段为对话流，等待/审批卡和附件卡保持原位。
- 顶部或底部使用轻量分段：对话、任务、输出物、统计；定时等低频项放入更多菜单。
- 底部为输入/附件/发送动作栏；离开详情回到进入前的收件箱或来源页。

#### 手机屏 3：团队待办与看板

- 团队 root 首屏为待确认、待验收卡；下滑进入成员状态和任务板摘要。
- 团队详情以横向分段切换对话、看板、成员、活动；确认卡固定在可见区域。

#### 手机屏 4：项目只读观测页

- 顶部项目路径与风险计数；下方是四个聚合分节卡：会话、团队、输出物、验收单。
- 所有卡片以“查看原始域”作为动作，明确项目页不直接编辑。

#### 手机屏 5：设置与连接

- 设置 root 使用列表式入口：连接与设备、模型服务、显示与快捷键、团队身份、扩展、关于。
- 连接状态卡置顶；配对和凭证录入遵守设备能力边界，手机承担浏览、验证和换路由。

### 视觉基调

深蓝黑底、暖橙行动色、低饱和蓝灰信息层；高密度、强层级、少装饰；面板像专业控制台，状态用短标签和细线强调，关键动作使用橙色实体按钮。动效只服务于“状态变化、来源跳转、确认完成”。

### 优劣

- **优势：** 最适合 PM/架构师高频处理多个并行会话、团队风险和验收动作，功能覆盖与行动优先级天然匹配。
- **劣势：** 桌面三栏和手机行动收件箱都需要较强的信息密度控制，新用户需要理解“队列 + 检查器”的工作方式。

## 方向 B：工作空间 Workbench

### 设计理念

**把每个一级域做成一个可持续工作的空间：导航稳定，内容像 IDE 一样可组合、可聚焦。**

### 信息架构与导航模型

#### 桌面 Web

- **空间切换：** 顶部为全局工作空间切换器，左侧为当前空间的上下文索引；四个正式空间为会话、团队、项目、设置，通知是顶部全局收件箱。
- **三栏结构：** 左侧 72px 全局空间栏；中侧 240px 当前空间索引树；右侧为可拆分画布。用户可以在同一空间内保留一个主实体和一个辅助实体。
- **会话空间：** 索引树按项目/服务器/状态组织；主画布可以是对话，旁栏可以钉住任务或输出物。
- **团队空间：** 索引树是团队和成员；画布在看板、成员、派单、确认单之间切换。
- **项目空间：** 索引树是目录；画布展示只读聚合，所有编辑动作打开原始空间的工作区。
- **设置空间：** 采用左侧分组导航和右侧表单/状态卡；通知作为独立收件箱抽屉，不改变当前空间。

#### 手机 Expo

- **底栏四域：** 会话、团队、项目、设置；每个 root 都是该空间的“入口页”，详情以面包屑/顶部返回深入。
- **空间内导航：** 不使用大量固定底部 Tab；以顶部标题下的分段、可展开索引和半屏 sheet 承载次级视图。
- **状态保留：** 每个 root 记住最近打开的实体和子视图，但详情返回仍严格按来源栈处理。
- **通知：** root 顶栏铃铛打开行动收件箱；处理后回到原空间，不把通知做成第五个内容域。

### 关键屏结构

#### 桌面屏 1：会话工作台

- 左侧空间栏显示四域；中侧索引列出项目、源和会话分组。
- 右侧画布上方为会话标题和子视图分段，下方左右分割：左半对话流，右半可切换任务、输出物、用量和审批详情。
- 图片/文件预览作为画布内浮动层，关闭后回原滚动位置。

#### 桌面屏 2：团队工作台

- 中侧索引列出活跃团队、归档团队和待处理数量。
- 右侧画布顶部为团队摘要；主体可切换看板、成员表、派单流、确认卡清单。
- 选中成员后打开右侧窄检查器，展示当前任务、分支、上下文、心跳和接替动作。

#### 桌面屏 3：项目工作台

- 左侧目录树按 realpath 展示项目；中央显示项目四分节聚合。
- 右侧为“来源路径”面板，列出每个聚合条目的原始会话/团队入口和最后更新时间。
- 页面不出现编辑型主按钮；跳转按钮明确标注目标工作空间。

#### 桌面屏 4：设置/通知空间

- 设置为稳定表单空间：连接状态卡、服务器列表、模型服务、显示、快捷键、扩展和关于按分组排列。
- 通知以右上角抽屉打开，抽屉内 action alert 有明确“去处理”按钮，处理后保留已完成历史但不再计 badge。

#### 手机屏 1：会话空间首页

- 顶部显示空间标题、搜索和铃铛；内容为项目分组会话列表，首行可固定“待处理”。
- 点击会话进入详情；长按或更多菜单处理重命名、归档、删除等列表动作。

#### 手机屏 2：会话详情工作区

- 顶部面包屑显示“会话 / 项目 / 会话名”；标题下为可横滑的对话、任务、输出物、统计分段。
- 审批/等待卡以全宽固定卡呈现；输入栏固定底部；返回按面包屑来源而非固定跳列表。

#### 手机屏 3：团队空间

- 首屏为团队选择器、待确认卡和成员状态摘要；进入团队后用顶部段签切换对话、看板、成员、活动。
- 看板采用可折叠泳道，任务卡点击打开半屏详情，派单/确认动作固定在详情底部。

#### 手机屏 4：项目空间

- 项目列表以目录卡呈现，卡上标注会话数、团队数、输出物数和行动风险。
- 项目详情为纵向只读聚合；点击条目生成明确的来源跳转链路，返回时恢复项目滚动位置。

#### 手机屏 5：设置空间

- 设置首页是分组列表；连接与设备置顶显示在线/异常状态。
- 模型服务、扩展、关于等进入二级页面；配对使用全屏流程，完成后返回设置来源页。

### 视觉基调

中性深浅双主题、纸张/工作台隐喻、暖橙作为当前工作区和主动作色；密度中等，边框和分割线清晰，局部可有轻微磨砂层。强调稳定、可预期、可恢复，不依赖大量动画。

### 优劣

- **优势：** 最容易扩展新功能和新实体，桌面与手机都能通过“空间 → 详情 → 子视图”形成稳定心智模型。
- **劣势：** 多一层索引和工作区概念，处理突发告警不如方向 A 直接，项目聚合也可能被用户误解为可编辑空间。

## 方向 C：信号流 Signal Stream

### 设计理念

**把 cc-deck 设计成一条持续更新的运营信号流，用户先处理最重要的变化，再按实体深入。**

### 信息架构与导航模型

#### 桌面 Web

- **主入口：** 桌面启动后进入“今日信号”视图，按行动优先级汇总会话等待、团队确认、验收、连接异常和成员失联；这不是新的业务域，而是会话域的默认总览模式。
- **正式域：** 左侧信号栏仍有会话、团队、项目、设置四个一级入口；通知铃铛只打开行动信号过滤器，不单独占内容域。
- **时间线 + 透镜：** 主区是按时间排序的事件/行动时间线；顶部透镜切换全部、会话、团队、项目。点击事件后右侧展开实体上下文，必要时进入详情。
- **详情：** 详情页是事件流的深层页面，保留对话、任务、输出物、统计等局部视图；返回按事件来源回到原时间线位置。
- **项目：** 项目作为独立透镜和一级页，展示项目事件与只读聚合；所有写操作回到会话或团队事件源。

#### 手机 Expo

- **底栏四域：** 会话、团队、项目、设置；会话 root 的默认视图就是“行动流”，可切换“全部会话”。
- **行动流卡片：** 每张卡包含事件、对象、严重性、下一动作和时间；向左/更多菜单提供已处理、稍后处理、查看来源等动作。
- **团队与项目：** 团队 root 默认显示团队信号和任务板摘要；项目 root 默认显示项目变化和风险摘要。
- **通知：** root 顶栏铃铛只过滤出跨域 action alert；处理后返回原行动流位置。

### 关键屏结构

#### 桌面屏 1：今日信号 / 会话域

- 左侧信号栏显示四域、连接状态和铃铛；主区顶部为“需行动 / 运行中 / 已完成”过滤。
- 中央时间线混排会话等待卡、团队确认卡、验收卡和连接告警；卡片颜色只表达优先级，来源图标表达所属域。
- 右侧上下文面板展示相关会话片段、团队成员、任务进度或验收证据，并提供“打开原始详情”。

#### 桌面屏 2：会话详情流

- 左侧为该会话的时间轴导航；中央是对话流和内嵌的任务/审批/文件/图片卡；右侧显示用量、输出物和待办。
- 每个等待卡可以直接允许/拒绝或跳到权限设置；完成动作后事件流实时插入结果。

#### 桌面屏 3：团队脉搏

- 顶部显示团队健康摘要和行动数量；中央按时间流展示认领、提交、停滞、待验收、接替等事件。
- 右侧提供“切换到看板”视图，把事件流转换成任务泳道；成员卡可查看心跳、分支、上下文和派单。

#### 桌面屏 4：项目脉络图

- 项目页把目录作为主锚点，中央按时间/实体显示会话、团队、产物、验收之间的关系链。
- 右侧风险面板聚合需行动项；每条都跳回原始域，不直接编辑项目聚合数据。

#### 手机屏 1：行动流首页

- 顶栏为连接状态、搜索、通知；首屏按优先级显示等待确认、待装机、待验收、连接异常和团队停滞。
- 每张卡都包含单一主动作，例如“允许”“去验收”“查看团队”“重连”，避免多动作竞争。

#### 手机屏 2：对话详情流

- 对话、任务、输出物、统计以顶部轻量分段切换；事件卡内直接显示审批和附件。
- 页面底部是输入栏或当前事件的主动作栏；返回恢复到原行动流的滚动位置。

#### 手机屏 3：团队脉搏与看板

- 团队首页先显示“发生了什么”和“现在卡在哪里”，成员列表与看板作为两个可展开分区。
- 团队详情可在事件流和竖向泳道间切换；确认卡保持置顶，接替动作放在成员详情。

#### 手机屏 4：项目风险流

- 项目卡显示目录、最近变化、风险和实体计数；详情以纵向脉络流展示四类只读聚合。
- 点击条目打开来源详情；返回后保留项目时间线锚点。

#### 手机屏 5：验收与通知处理 sheet

- 通知铃铛进入行动列表；验收项以底部 sheet 展开，逐项回填、提交回填、确认收单三步状态始终可见。
- 完成后回到通知/行动流，badge 只在 alert 真正处理或关闭后减少。

### 视觉基调

深色高对比、信号色驱动、时间线和状态点为主要视觉语法；暖橙表示 cc-deck 主动作，红/琥珀/蓝/绿分别表达需行动、注意、待验收、运行/完成。强调实时感、轻微呼吸和流入动效，但必须提供静态状态和减少动效选项。

### 优劣

- **优势：** 最快把用户注意力带到真正需要处理的变化，适合并行团队和长时间运行任务的值守场景。
- **劣势：** 事件分类、去重、历史检索和“为什么出现在这里”的解释成本最高，信息流过密时容易产生疲劳。

## 方向横向比较

| 方向 | 核心心智 | 桌面最强点 | 手机最强点 | 主要风险 | 更适合的产品阶段 |
|---|---|---|---|---|---|
| A 指挥桥 | 我现在要做什么 | 多栏并行决策与证据核对 | 待处理优先、动作直达 | 密度高、实现复杂 | 团队编排和验收成为主场景后 |
| B 工作空间 | 我正在在哪里工作 | 可扩展、可恢复、实体边界清晰 | 稳定的空间/详情心智 | 突发事项不够聚焦 | 功能面持续扩张、需要长期可维护性 |
| C 信号流 | 刚刚发生了什么 | 跨域行动一屏汇总 | 实时提醒与单动作处理 | 信息噪声和分类成本 | 并行运行、监控和告警占主导后 |
