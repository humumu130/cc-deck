# cc-deck IA 冻结与状态矩阵

冻结日期：2026-10-03  
依据：用户对 `specs/000-ui-skeleton-review.md` 的拍板；本文件冻结第 0 步结果，作为后续 UI 骨架和路由实现的边界。

## 1. 四 Tab 决议记录

### 决议

手机一级导航固定为四 Tab：

1. 会话
2. 团队
3. 项目
4. 设置

项目确认为长期一级域，采用**只读聚合**模型：项目页展示按目录聚合的会话、团队、输出物和验收信息；任何写操作、状态变更或原始实体编辑，必须跳回会话域或团队域的原始写面，不在项目域复制一套写入口。

### 拍板依据

- `docs/v8-ui-mockup.html` 的 V8 增量段已经将项目列为桌面 rail 和手机底栏入口。
- `docs/v8-ui-interactive-v2.html` 的可点击原型已按四 Tab实现，`PH_ROOT` 也将会话、团队、项目、设置定义为四个 root。
- 桌面 rail 与手机底栏需要共享同一张一级导航地图；保留三 Tab 会使项目在桌面存在、手机消失，造成跨端信息架构不一致。
- 项目只读聚合、联动回原域的边界可以避免项目域成为第二套会话/团队写面。

### 导航层级原则

- 一级域负责跨实体、跨模块的工作面切换。
- 详情页负责单个实体的上下文和动作，不显示手机底栏。
- 详情内的子 Tab 只切换当前实体视图，不承担一级域跳转。
- 通知是跨域行动入口，不占手机底栏 Tab；桌面放在 rail 铃铛，手机从 root 顶栏铃铛进入通知二级页。

## 2. 桌面 rail 最终项目清单

rail 宽度、视觉和位置沿用设计稿：固定 56px、纯图标、顶部连接状态绿点、底部弹簧区分隔内容域与工具入口。

| 顺序 | 项目 | 类型 | 选中/角标规则 | 目标路由 | 说明 |
|---|---|---|---|---|---|
| 顶部 | 连接状态绿点 | 状态/快捷入口 | 绿/黄/红表达连接状态，不计数 | `settings/connections` 快览 | 点击先开连接快览；进入完整连接页时回设置域 |
| 1 | 会话 | 一级域 | 品牌橙选中，无一级 badge | `/chat` | 默认启动域；承载会话列表和会话详情 |
| 2 | 团队 | 一级域 | 品牌橙选中；团队 badge 独立显示 | `/team` | 承载进行中团队、归档团队和开团入口 |
| 3 | 项目 | 一级域 | 品牌橙选中，无默认 badge | `/project` | 目录聚合只读；写操作跳回原域 |
| 弹簧后 | 通知铃铛 | 跨域工具入口 | 红色数字只计需行动 alert | `/notifications` | 不作为内容域，不占手机底栏 |
| 底部 | 设置 | 一级域 | 品牌橙选中，无默认 badge | `/settings` | 设置升级为独立 root；连接、模型服务等为设置子页 |

rail 点击规则：

- 点击一级域切换当前工作面，并更新桌面 URL/history；不把详情内子 Tab误当成 rail 状态。
- 点击通知只打开通知面板或通知二级页，不改变当前内容域的归属；关闭后恢复原工作面。
- 点击绿点只打开连接快览，不改变当前内容域；从快览进入完整连接页时进入设置域的连接子页。
- rail 选中态只允许一个一级域；通知打开态是工具态，不覆盖域状态。

## 3. 三层路由表

### 3.1 路由层级定义

- **域（Domain）：** 一级工作面，对应桌面 rail 和手机四 Tab。
- **详情（Detail）：** 某个域内的实体或二级页面；手机详情页隐藏底栏。
- **子 Tab（Sub-tab）：** 当前详情的局部视图。没有真正 Tab 的详情使用固定子视图/分节名表示，不能借此新增一级入口。

### 3.2 主路由表

| 域 | Root 路由/页面 | 详情路由/页面 | 子 Tab / 子视图 | 写入边界 |
|---|---|---|---|---|
| 会话 | `/chat` 会话列表 | `/chat/:sessionId` 会话详情 | `activity` 对话、`todos` 任务、`all` 全部、`artifacts` 输出物、`cron` 定时、`stats` 统计 | 会话消息、任务、权限、输出物等原有动作仍在会话详情完成 |
| 团队 | `/team` 团队列表/开团入口 | `/team/:teamId` 团队详情 | `chat` 对话、`board` 看板、`members` 成员、`activity` 活动 | 团队目标、编制确认、成员动作和看板动作归团队域 |
| 项目 | `/project` 项目列表/目录聚合 | `/project/:projectId` 项目详情 | `sessions` 会话、`teams` 团队、`artifacts` 输出物、`acceptances` 验收单四个只读分节 | 项目域不产生第二写面；点击动作跳 `/chat/:sessionId` 或 `/team/:teamId` |
| 设置 | `/settings` 设置主页 | `/settings/:section` 设置子页 | `general` 通用、`providers` 模型服务、`connections` 连接与设备、`team-identity` 团队身份模板、`extensions` 扩展、`about` 关于 | 设置写入只在设置域；手机凭证录入仍遵守“回电脑/网页端”边界 |
| 通知（工具） | 不占 root Tab；桌面 rail 面板、手机 root 顶栏入口 | `/notifications` 通知中心/行动清单 | `action` 需你行动、`attention` 注意、`activity` 动态为分组，不是详情 Tab | 通知行的动作跳原始域；通知中心本身不复制业务写操作 |

### 3.3 平台映射

| 平台 | Root 导航 | 详情导航 | 返回/恢复 |
|---|---|---|---|
| 桌面/网页 | rail：会话 / 团队 / 项目 / 设置；通知为 rail 工具入口 | 详情头部与详情 Tab 保留；项目详情使用只读分节 | 域、详情、子 Tab 纳入 URL/history，可刷新恢复 |
| 手机 | 底栏四 Tab：会话 / 团队 / 项目 / 设置；通知从 root 顶栏铃铛进入 | 详情页隐藏底栏；使用页面头部返回 | root 保留最近 root；详情按来源栈返回，不强制持久化详情 |

### 3.4 URL/history 约定

桌面 URL/history 至少能恢复以下三项：

1. 当前域，如 `/team`。
2. 当前详情实体，如 `/team/team-1`。
3. 当前子 Tab，如 `/chat/s-1?tab=todos`。

约定：

- 根域切换产生可回退的 history 状态；同一详情内切换子 Tab可以更新 history，但不得创建不可控的重复历史噪声。
- 刷新或直接打开深链接时，先恢复域，再恢复详情，最后恢复子 Tab；实体不存在时退回对应 root并给出轻量提示。
- 通知面板打开/关闭属于临时工具态；若进入通知中心二级页，则按详情/二级页进入 history。

## 4. Badge 计数口径

团队和通知必须使用两个独立计数器，不能用同一个“未读总数”字段互相替代。

### 4.1 团队 badge

| 项目 | 冻结口径 |
|---|---|
| 计数对象 | 当前用户需要在团队域处理的行动项 |
| 纳入 | 待用户确认的编制/目标决策；就绪待装机、待验收或待确认收单事项 |
| 不纳入 | 普通团队动态、成员心跳、已读聊天、一般 warning/info、仅 AI 自验通过但不需用户动作的事项 |
| 去重 | 以团队行动项/验收单稳定 ID去重；同一事项不因多个来源入口重复增加团队 badge |
| 清零 | 用户完成确认、提交回填、确认收单，或明确处理该行动项后清零对应项 |
| 展示 | 仅显示数量；超过 99 显示 `99+`；无数量时隐藏角标 |

团队 badge 表示“团队域还有多少工作需要我处理”，不是团队消息未读数。

### 4.2 通知 badge

| 项目 | 冻结口径 |
|---|---|
| 计数对象 | 跨域、需要用户采取行动的 active alert |
| 纳入 | 需验收/收单、成员失联需接替、连接或设备异常需处理等常驻行动告警 |
| 不纳入 | 可自愈 warning、普通 info、已读动态、任务完成汇报、仅提示性质的状态变化 |
| 去重 | 以 alert ID去重；同一 alert 在桌面铃铛和手机铃铛只计一次 |
| 清零 | 用户执行行动、在通知中心明确关闭/已处理，或后端将 alert 标记为 resolved |
| 展示 | 红色数字角标；只在数量大于 0 时显示；不因打开面板自动清零 |

团队 badge 与通知 badge 可以因为职责不同而同时显示同一底层事项：团队 badge 表示团队域待处理工作量，通知 badge 表示跨域行动告警量；两者各自去重、各自清零，不互相覆盖。

## 5. 返回栈规则

### 5.1 统一优先级

所有平台按以下优先级消费返回：

1. 关闭当前打开的弹窗、底部 sheet、通知面板、连接快览或其他临时浮层。
2. 若处于详情页，返回来源页/来源域；不能无条件跳会话 root。
3. 若处于设置子页、通知中心或项目详情等二级页，返回其来源 root或来源详情。
4. 若已经在 root，桌面交给浏览器 history；移动端回到上一个 root或交给系统退出规则。

### 5.2 来源栈要求

- 从项目详情跳到会话详情，返回应回到原项目详情；从项目详情跳到团队详情同理。
- 从通知 alert 跳到原始会话/团队/设置页，返回应回通知中心；再次返回才回通知进入前的 root。
- 从验收单入口跳入会话任务视图，返回应回触发验收单的列表/团队/通知来源，不丢失原入口上下文。
- 直接通过 URL/history进入的页面没有来源栈时，按所属域 root作为后备返回点。

### 5.3 桌面与手机行为

- **桌面：** rail 切域不是详情返回；切换到另一域后保留各域最近 root/详情状态，但当前 URL只表达当前域。浏览器后退按 history 恢复之前的域、详情和子 Tab。
- **手机：** 点击底栏切换 root 不把每次 Tab 点击堆入详情返回栈；每个 root可保留最近 root 状态。进入详情后隐藏底栏，头部返回、系统返回和边缘返回均走同一来源栈。
- **详情内子 Tab：** 子 Tab切换不改变来源栈；可以同步桌面 history或移动端内部状态，但返回不会逐个穿过所有子 Tab。
- **动画期间：** 进入/退出动画未完成时暂不接受第二次导航动作；不得因动画守卫吞掉系统返回，需在动画结束后恢复可消费状态。

## 6. 实施前验收基线

- 桌面 rail 固定为：连接绿点、会话、团队、项目、弹簧、通知铃铛、设置。
- 手机底栏固定为四 Tab：会话、团队、项目、设置；项目详情、团队详情、会话详情、通知中心、验收单等二级页面隐藏底栏。
- 项目域只读聚合，所有写操作回到会话域或团队域；通知只作为跨域行动入口。
- 团队 badge 与通知 badge 分列、分口径、分清零；普通动态和任务完成汇报不进入一级角标。
- 桌面可通过 URL/history恢复域、详情和子 Tab；移动端详情按来源栈返回，root只保留最近 root状态。
- 本文件冻结后，后续 UI 细化不得重新引入三 Tab、项目域可写或通知占用底栏等变体；若要改变，必须新开决议记录。
