# UI 设计军规（PM 设计单执行手册）

- 用途：specs/005/004 一切设计单的执行准则。每张设计单交付前过 §9 自检清单。
- 来源：Leader 设计经验沉淀（参考 Claude 侧 impeccable / ui-ux-pro-max / apple-design 三套规范体系提炼），2026-10-03 立。

## 1. 总纲三问（动手前先答）

1. 这个界面是**什么**（导航/实体浏览/配置/瞬时状态）？形态跟着答案走，不跟着习惯走。
2. 用户**第一眼**要拿到什么信息？把它放在扫视路径起点（左上→右下，F 型）。
3. 用户**下一步动作**是什么？每屏至多一个主按钮（brand 色），次要动作降级（描边/幽灵/文字链）。

## 2. 布局与形态

- **卡片=可选择的实体**（会话/任务/成员/输出物）；**列表行=导航与配置**。同一信息不出现两遍（源标签密度原则、状态标签不与泳道重复）。
- 密度分级：浏览型界面行高 ≥40px；管理型可到 32px；绝不为省空间牺牲可点目标（≥28px 高）。
- 分组优先用**留白+小节标题**，其次分割线，最后才框。嵌套卡片 ≤2 层，第 3 层必是列表。
- 8px 网格：间距取 4/8/12/16/24/32，不出现 13、22 这类任性值。

## 3. 色彩纪律（铁律）

- **token-only**：一切颜色走语义 token，硬编码色值=打回（含 rgba 透明度变体）。新色先入 004 色板表（暗/浅双列）再用。
- 语义色各司其职：brand=主行动、done=成功、working=进行、error=失败、info=中性强调。**不拿语义色做装饰**。
- 浅色不是反色：浅色下阴影减淡、边框加深、饱和度降档，逐 token 校准（不是 filter:invert）。
- 大面积底色永远低饱和；高饱和只出现在小面积标识（点/标签/主按钮）。
- 文本对比度：正文 ≥4.5:1，辅助 ≥3:1，两套主题分别验。

## 4. 排版

- 字号阶：12/13/15/17/20/24，不出现 14/16/18 之外的任性值；界面主体 13。
- 字重两档用到底：常规 400 + 强调 600，慎用 500（中文渲染发虚）。
- 数字等宽（font-variant-numeric: tabular-nums）：一切会变化的数值（计数/延迟/用量）。
- 中文细节：中西文间加空格感的字距（letter-spacing ≥0.2px）；标点悬挂禁用；省略号截断代替折行爆炸。

## 5. 组件态清单（每个可交互组件八态）

hover / active / focus-visible（键盘可达）/ disabled / **空态**（一句话+一个动作，不是白板）/ 加载态（骨架屏>转圈）/ 错误态（出了什么事+怎么办）/ 溢出态（长文本/多标签截断规则）。缺态=未完成。

## 6. 图标与标识

- 图标 16/18/20px 三档，线宽统一（同屏不混 1.5px 和 2px 线）。
- 图标+文字永远优于纯图标；纯图标必须有 title+aria-label。
- 徽标/角点直径 ≤8px，一个图标至多一个角点。
- 双标识体系：引擎标×源标按既定顺序与填色规则（order18 落定后引用）。

## 7. 动效

- 时长 120~200ms、ease-out；只有 transform/opacity 走过渡（不过渡 top/height）。
- 动效只答两个问题：**东西从哪来**（弹层自触发点）**、什么变了**（状态切换微动）。答不出的动效删掉。
- prefers-reduced-motion 尊重。

## 8. 双端对齐

- 桌面改什么，手机必须有对应答案（可不同形态，不可缺失）。
- 手机触控目标 ≥44×44；底部操作优先（拇指区）；桌面 hover 提示的信息在手机上要有落点。
- 每屏手机高度内必有一个可执行动作，不许整屏纯展示。

## 9. 交付自检清单（每单摘要前默过）

- [ ] 零硬编码色值（grep 复核）；新 token 已入 004 双列
- [ ] 每个可交互元素八态齐（至少 hover/disabled/空态）
- [ ] 同一信息没出现两遍
- [ ] 主按钮每屏至多一个
- [ ] 文本对比度两主题达标
- [ ] 手机端有对应答案
- [ ] 数字等宽、间距 8px 网格
- [ ] 「看着能交互的都真能交互」（原型完整性铁律）

## 10. 禁忌清单（历史教训）

- 汉字水位条式粗糙可视化（order23 起改分段色带/环形）
- 全卡片化偷懒（order22 起：形态随功能走）
- 菱形等抽象符号代替通用图标（order13 起铃铛先例）
- 浅色下灰成一团/黑块（token 纪律）
- 占位假 Tab（点击无效的 Tab 不许上屏）

## 11. 术语速查表（新人 30 秒）

> 角色词条按组织模型 v2（018 §9；评审论证见 codex-minstaff-review.md §14/§16/§17）；工程词条与 018 §8.5 建议清单一一对应。

- **PM**：每团队常驻重角色——分诊/任务书/派单/验收链/巡检/代提交/rescue；A 模式直接对用户。旧文档里承担调度的「Leader/架构师」即 PM。
- **薄 Leader**：仅 B 模式存在的全局薄角色——路由/聚合/提醒/升级；无验收权无 commit 权，开关插拔；A 模式=用户自占 Leader 位不占卡。
- **评审卡**：临时专家角色——盲评/复审/高风险验收，`proposed→active→retired` 跑完即删；旧「临时 PM/Codex 专家卡」语义归此。
- **relay**：每台工作机的本地服务核心（8787），会话生命周期/命令路由/事件广播/快照的唯一业务真相源。
- **source**：一个 relay 连接在一端的身份（多源列表的行单位），跨源同路径不合并。
- **SNAPSHOT**：全量状态快照帧，断线恢复/首连用；LAN 与云桥双出口必须同构。
- **event**：relay 广播的状态变化帧（`SESSION_UPDATED` 等），客户端只是投影；审计事实在 `events.ndjson`。
- **COMMAND**：客户端→relay 的命令帧（`COMMAND_CREATE` 等），必须进白名单才被受理。
- **ACK**：relay 对命令的回执（同 `command_id`），`ok:true` 严格判定才算成功，超时/`ok:false` 可见可重试。
- **dispatch_id**：一张派单的全链路追踪 id（dispatched→running→done/failed）。
- **command_id**：单条命令的幂等键，重复回放首次 ACK，不二次执行。
- **projection**：客户端从事实源派生的只读视图，不建第二状态库。
- **task-store**：引擎原生任务记录（CLI 自己的 todo/任务文件），relay 不冒充它。
- **artifact store**：输出物登记与拉取层；文件本体留在源机器，跨端 E2E 拉取。
- **status dock**：会话状态舱——任务级摘要段+操作级活动段双段结构。
- **指标带**：项目聚合的度量行（会话数/活跃团队/输出物/需行动），计数只来自实际渲染口径。
- **列表行**：导航与配置用的行形态（区别于卡片=可选实体）。
- **轻量分组行**：输出物目录组/通知分组头一类轻量行，只带计数与折叠，不复制内容。
- **member archive**：项目组的不可变成员身份快照，成员退休后历史消息仍显示归档身份。
- **parity matrix**：SNAPSHOT 逐字段×三出口（LAN/cloud/WAN）的对照事实表，新字段先登记再进客户端。
- **reconciliation probe**：派单对账探针，判定 orphan/duplicate/timeout/seq-gap 四类异常。
